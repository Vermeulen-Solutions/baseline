# Website brand assets

Read for a requested logo/icon refinement, favicon, asset variants or a coherent icon family. Reuse the existing brief, supplied mark and selected canvas. A website redesign does not by itself authorize replacing the identity. Distinguish preserving/exporting an existing mark, refining it and creating a new identity; resolve only an unsettled distinction that changes the work.

## Work from the real master

Inspect the native/vector source, its actual paths, fonts, colours and intended placements. Keep the original unchanged. Extract an existing symbol from a lockup when appropriate; do not shrink the entire wordmark/tagline into a favicon. Preserve geometry during extraction. A simplified small-size companion is a proposed variant, not silently the new master. Keep identifiable letters and meaningful negative space.

For a new mark, use the site's settled identity brief and compare a small set of meaningfully different ideas before developing the chosen one. Do not repeat a full discovery interview or generate a complete identity kit unless that is the assignment. Native vector tools and authored SVG are valid paths; a raster concept is not editable vector delivery.

## Prove the intended use

- Put the asset beside its source in a compact review sheet. Render the actual intended sizes, commonly 16/24/32px for a symbol and its real header size for a lockup; enlarging a screenshot does not prove small-size legibility.
- Inspect counters, gaps, stroke consistency, unintended clipping and optical weight. Check one-colour and reversed versions on the actual intended grounds. Preserve a supplied colour-dependent mark; propose a deliberate monochrome variant rather than flattening gradients indiscriminately.
- For an icon family, agree one source family or construction language: grid, stroke/fill, corners, optical size and naming. Check an action, a navigation icon and a status icon together. Label icon-only controls; hide purely decorative icons from assistive technology. A brand/service logo lookup is separate from drawing generic UI icons.
- Keep SVG `viewBox`, transparency and identifiers usable. Avoid external font/image dependencies in a portable symbol; preserve an approved live-text wordmark when outlining or substitution is outside scope, and state its font dependency. Repeated inline instances need unique internal IDs. An `<img>` needs appropriate HTML alternative text; SVG titles alone do not name its enclosing control.

Deliver only the variants the website needs, with source identity, changed-versus-preserved properties and observed sizes in existing notes. Use the site's media preparation/preservation rules for production assets. Do not claim originality clearance, print suitability, native-canvas editability or a tested minimum size from a browser-only export check.
