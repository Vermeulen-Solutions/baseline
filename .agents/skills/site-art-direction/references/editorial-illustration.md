# A coherent website illustration set

Read when a site needs related article, service, process, hero or empty-state illustrations. Reuse the accepted direction and real content. A request for one image does not require a whole system or additional service.

## Plan what the pictures explain

For each needed image, name the page/topic, the reader's question, the idea the image adds, the placement/crop and whether it is informative or decorative. Avoid an interchangeable stock metaphor or an image for every heading. Keep essential instructions, claims and diagram labels available as HTML/text as appropriate; invented results and simulated successful submissions are not visual proof.

Define the shared visual language once in the current concept notes: palette roles, geometry or line treatment, perspective, level of detail, lighting/material where relevant, framing and background/transparency. Also name what varies with the topic. Use one useful approved reference when it exists. Do not pin every object and position so tightly that different topics collapse into copies of the same composition.

## Choose the medium for the deliverable

Use supplied photography or an available image-generation/editing skill for a picture. Use native vectors/SVG for requested editability, exact diagrams or geometric construction, and the selected canvas when it is the owner's working surface. A requested native or SVG illustration, including purposeful shaded/perspectived construction, is permitted by this Baseline-owned route: the selected medium and approved brief take precedence over upstream Impeccable's generic picture-format restriction. Keep its quality intent—no crude stand-in scenes—and inspect the actual construction. Do not alter the upstream mirror or silently replace an editable asset with a bitmap.

Model-driven technical figures may use a specialist such as [Anatomy](https://github.com/wheresryan22/anatomy/blob/689dcf966e63d92be10a5d593c6e19e10acd4422/SKILL.md) when the brief calls for it. Its machine aesthetic, part counts and renderer are not defaults for service websites. Use existing `impeccable/reference/overdrive.md` for requested ambitious effects before discovering another generic skill.

## Review one slice before expanding

For a set, make a representative pair first and view them together at intended placements. Inspect consistent visual weight, topic-specific meaning, narrow crops, light/dark grounds when used, fine detail and any generated text. A consistent palette alone does not establish a coherent set. Informative illustrations need meaningful alternatives or adjacent explanation; decorative ones should not add redundant announcements.

Then produce the remaining authorized assets with that language, retaining source/reference identity and draft-versus-selected status in existing notes. Prepare production files through the site's media workflow; inspect the prepared output. Report exact media/variants checked rather than claiming native editability or successful browser integration from a PNG alone.

Planning ideas are informed by [Illustration Style](https://github.com/Owl-Listener/designer-skills/blob/9a6930cf84a822eb458624bd11c61aac5bbdf224/ui-design/skills/illustration-style/SKILL.md) and [Article Illustrator](https://github.com/JimLiu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-article-illustrator/SKILL.md). Reuse available backends and established context instead of importing their preference files or confirmation workflow.
