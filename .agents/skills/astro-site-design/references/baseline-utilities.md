# Baseline utilities in src/styles/global.css

Read when a page or component needs one of the families below. The utilities exist in every Baseline site's `src/styles/global.css` and shell; check the installed file before using one on an older site, because it may predate a family. Reuse a utility rather than writing a parallel one, because each carries accessibility, reduced-motion and surface-mode behaviour that a one-off copy loses.

## Choose the family

| If the page needs… | Use | Why this one |
| --- | --- | --- |
| Headline hierarchy, labels, metadata or numbers | Typography voices (display, `.font-accent`, `.eyebrow-telemetry`, `.tabular-nums`) | Display and body always; accent and mono only where the content earns them, so the roles read as a system rather than decoration; tabular figures stop numbers shifting width as they change |
| Depth between sections, cards and controls, or a rhythm breaker mid-page | Surfaces and grids (3-tier surfaces, `.bento-grid`, `.grid-hairline`) | Depth from tokens survives dark mode and contrast checks; hand-picked greys and shadows do not |
| Primary, secondary and tertiary actions; a sticky header | Actions and shell (`.btn` variants, `data-sticky-header`) | One hierarchy across the site; the shell already handles scroll state and focus |
| A product, data or developer-tool hero without honest photography | UI specimens (`.ui-specimen`, `.viz-bars`) | Live HTML stays sharp, accessible and editable; raster screenshots and stock art do not |
| Card stacking, reveals, filtering, a theme switch or a small calculator | Micro-islands (`.stack-cards`, `data-reveal`, `data-filter-*`, `data-surface-toggle`, `define:vars` scripts) | Progressive enhancement with no framework runtime; content still works without JavaScript |
| Client-side navigation, morphing cards into articles, prerendering | Page transitions (`<ClientRouter fallback="swap" />` with the shell's guards) | The shell's timings and editor guards are already tested; a new router setup would bypass them |
| Self-hosted fonts, inline SVG icons, per-visitor blocks on cached pages, validated forms | Astro platform features (`fonts` API, SVG components, `server:defer`, `astro:actions`) | Native features avoid extra dependencies and keep CLS and caching under Astro's control |

Use a family only for a visitor need. A feature count is not a quality measure, and an unused motion or surface utility adds weight and review work.

Two rules from this file apply to every page and are repeated in the skill: keep adjacent inline elements on one line or join them with `{' '}` (Astro v7 `compressHTML: 'jsx'` strips the newline between them, which concatenates words), and give the above-the-fold hero image `loading="eager" fetchpriority="high"` (or `priority` on native `<Image />`/`<Picture />`), because it is usually the Largest Contentful Paint element.

## Recipes

Each family in full, with its selectors, attributes and timings:

- Pair `--font-display` headlines with `.eyebrow-telemetry` (`--font-mono` uppercase tags for real metadata such as dates, versions and status, never as a kicker above a heading or a decorative section coordinate), `.font-accent` (`--font-accent` inline italic serif contrast on 1–2 focal words inside `<h1>`/`<h2>`, only where the brand has that editorial voice), `.prose-dropcap` for editorial essays/manifestos, and `.tabular-nums` on all metrics/counters. **Astro v7 `compressHTML: 'jsx'` whitespace rule:** Astro v7 strips newline whitespace between adjacent inline elements; always keep inline spans/tags on the same line (`Engineered for <em class="font-accent">precision</em>`) or insert an explicit `{' '}` so words never concatenate.
- Layer 3-tier surfaces (`--color-page` canvas, `--color-surface` cards, `.surface-elevated` raised controls/headers, `.surface-glass` translucent bars, and `.surface-grain` zero-asset SVG paper/film texture) with `--surface-highlight` (`1px` top inner specular edge), `.bento-grid` (`.bento-span-4|5|6|7|8|12`, `.bento-row-2`), `.reel-snap` horizontal scroll-snap galleries, `.section-defer` (`content-visibility: auto`) on below-the-fold sections, native `<dialog>` `@starting-style` modals/drawers, and `.grid-hairline` / `.bg-grid-blueprint` / `.frame-crosshair` for architectural precision.
- Style actions with explicit hierarchy using `.btn` (primary solid), `.btn--secondary` (elevated surface with `--color-border-strong`), and `.btn--ghost`, pairing trailing arrows (`→` / `↗`) with `.icon-nudge` for spring-eased hover choreography; mark sticky site headers with `data-sticky-header` so `SiteShell.astro` toggles `data-scrolled` glass condensation after `16px` of scroll; and always pass `loading="eager" fetchpriority="high"` to above-the-fold hero `<ResponsiveImage>` components (or `priority` on native `<Image />` / `<Picture />`) for optimal LCP.
- For SaaS, developer tools, AI, fintech, and B2B sites, build the hero and flagship feature visuals as **live-coded HTML/SVG UI specimens** (`.ui-specimen` + `.ui-specimen__header` + `.badge-pill` + `.status-dot`) and pure-CSS telemetry histograms (`.viz-bars` + `.viz-bar` with `--bar-value`) rather than generic stock imagery. See [landing-page-archetypes.md](landing-page-archetypes.md) for copy-ready patterns.
- **Zero-framework micro-islands & declarative shell choreography:** Use `.stack-cards` + `.stack-card` (`--stack-index`) for zero-JS sticky physical card stacking; `data-reveal` + `data-reveal-delay` for progressive-enhancement scroll reveals; `data-filter-root` / `data-filter-btn` / `data-filter-item` for instant client-side category filtering with `.animate-card-in` reflow replay; `<SiteShell surface="dark|light|system">` + `data-surface-toggle` (with `[data-surface-icon="light"]` and `[data-surface-icon="dark"]` children) for FOUC-free persisted Daylight/Dark surface switching (`baseline:surface`) that preserves 3-tier `--color-page` / `--color-surface` / `--color-elevated` depth in both modes; and `<script define:vars={{ ... }}>` bound on `astro:page-load` for interactive ROI/pricing calculators or DAG/console node inspectors with 0 KB of client framework runtime.
- **Instant page transitions, hover image pre-decoding, shared-element morphing & Speculation Rules (`<ClientRouter fallback="swap" />`):** On `static` and `static-sveltia` sites (and public `emdash` routes guarded by `keepEditorNative()` so `/_emdash`, `?_edit=1`, and `#emdash-toolbar` preserve native browser navigation), slot `<ClientRouter fallback="swap" slot="head" />` from `astro:transitions` into `<SiteShell>` inside `Base.astro`. This pairs with `SiteShell.astro`'s 20ms hover HTML + `img.decode()` pre-warming (`warmPage`) and `astro:before-preparation` `80ms` image decode gate so incoming WebP images are already decoded in browser RAM before `startViewTransition()` captures the snapshot, `<head>` stylesheet deduplication, and `250ms var(--ease-smooth)` root View Transitions (with `data-vt-loading` delayed to `600ms` so fast navigations never flash a loading bar). Pass `loading="eager"` on primary card grids so card images paint in the initial transition snapshot rather than popping in after swap. Pass `transitionName={`post-${slug}`}` to `<Card>` on index pages and apply `.vt-morph` (`style={`--vt-name: post-${slug}-title`}`) on the detail route's `<h1>`/hero media to morph cards into full articles; for lists that render their own rows instead of `<Card>`, put `style={mediaTransition('post', slug)}` from `src/lib/view-transition.ts` on the list photo and the detail photo (ident-safe name plus the `vt-media` clip/cover class), and add `data-vt-header` to the sticky header so it does not ghost; use `transition:persist` on stateful header or media elements; and consider `experimental: { clientPrerender: true }` (Speculation Rules API) on static sites for 0ms background prerendering.
- **Native Astro 5/6/7 fonts, SVG components, Server Islands & Form Actions:** Configure custom Google, Fontshare, Bunny, Fontsource, or local fonts via Astro's built-in `fonts` API (`fontProviders` in `astro.config.mjs` + `<Font cssVariable="--font-display" preload />` from `astro:assets`) for self-hosted `.woff2` files and metric-matched zero-CLS fallback `@font-face` generation; import `.svg` files from `src/assets/` directly as inline Astro components with `.svg-icon`; use `server:defer` Server Islands with `<div slot="fallback" class="skeleton-shimmer">` for personalized/dynamic blocks on cached EmDash SSR pages; and use `astro:actions` (`defineAction({ accept: 'form' })`) for progressive-enhancement validated forms.
