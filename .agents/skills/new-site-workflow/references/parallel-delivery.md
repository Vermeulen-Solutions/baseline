# Bounded parallel delivery

Use when the user or applicable project guidance has authorized delegation and independent work would help. This is an optional coordination recipe, not a requirement to create agents, use another model, duplicate a brief or pause at another checkpoint. Keep the selected profile, existing decisions and agreed release endpoint.

## Split work by dependency and owner

| Work | Can progress independently | Waits for |
| --- | --- | --- |
| Content/schema planning | Route inventory, entity lifecycle, editing needs, realistic draft copy and evidence gaps in separately owned outputs | Shared field/URL decisions before dependent templates bind them |
| Route metadata and navigation planning | Search intent, title/description drafts, canonical/redirect requirements and existing-menu review | Settled route identities and authoritative facts before implementation |
| Direction and shared primitives | Representative concepts, token mapping, native component contracts and calibration under one writer | Known content shapes and the selected direction before broad rollout |
| Sibling route implementation | Separate route files using accepted shared contracts | Stable tokens, field/prop contracts, content ownership and representative-route proof |

While a consequential choice or build is pending, continue work that does not depend on its outcome. A route's copy draft may proceed while primitives are calibrated; sibling pages must not independently invent competing token systems or schemas to avoid waiting. Give uncertain upstream work a planning/read-only output until its implementation contract is settled.

## Issue a small work packet

Use the existing brief or tracker plus a short assignment: intended result; one owner; exact writable files or isolated instance; authoritative inputs and versions; dependencies; expected output and acceptance evidence; and explicit exclusions. Include the relevant profile and specialist references. The writer reports changed paths, source revision/contract used, checks actually run and remaining assumptions. Do not copy credentials, private session state or an entire project history into the handoff.

Use one writer per shared file, database instance and canvas document. Other agents can inspect and return a proposed change, or write a separately owned draft. Separate page IDs in the same canvas do not imply safe concurrent document writes. Integrate schema, shared CSS/component and navigation changes through their assigned owner; do not let agents overwrite each other's fixes. Reacquire current targets after another writer's completed batch.

## Integrate before claiming completion

The coordinating agent checks each result against current source and the agreed contract, resolves conflicts, and inspects the real integrated routes. Worker success is evidence for its bounded task; it does not establish cross-page consistency, editor round trips or release acceptance. Recheck affected consumers when a shared contract changes, and tell dependent writers which revision supersedes their input.

Freeze source writers before final verification and release. Merge the intended batches, run the installed checks and applicable browser/editor evidence against that integrated state, then complete the authorized commit/push/deployment endpoint. If source changes after a check, rerun the affected evidence. Keep unresolved human decisions visible while continuing independent authorized work; a queued task or running build is not a completed deliverable.
