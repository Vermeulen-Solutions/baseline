# Optional project context and document scope

The starter now offers `PROJECT.example.md` and a shared document-scope guide.
It keeps working rules and the existing Art Direction Record in `AGENTS.md`,
allows an explicitly adopted `PROJECT.md` for the client brief and nonvisual
decisions, and keeps selected `DESIGN.md` references/interchange separate from
implemented CSS and configuration. Progress belongs in the existing tracker or
a focused handoff. No mandatory project file or blanket precedence chain was added.

Both generated static profiles receive the example and guide without creating
`PROJECT.md`. Tests verify optional-document discovery without reading contents,
and preservation of client context, design and handoff files during bounded
updates even if they are accidentally classified as managed. No new runtime
dependency or configuration parser was introduced.

## Cold-resume checks

Two independent history-free sessions received the same synthetic workshop brief,
once in `AGENTS.md` and once in an adopted `PROJECT.md`. Each saw a stale handoff
suggesting CMS installation, an old unselected `DESIGN.md` export with fixed spacing,
later decision evidence, native static configuration and one typed workshop entry.
The frozen [protocol](protocol.json) describes the task and acceptance criteria;
each folder preserves its prompt, relevant inputs, result and resulting handoff.

Both trials passed the observations in [acceptance.json](acceptance.json):

- Recovered the audience, static English scope, exact email registration endpoint
  and editorial/maintenance ownership without renewed discovery.
- Kept quarterly cadence assumed and the launch deadline unapproved.
- Identified existing collection/content and missing listing/detail routes.
- Corrected the stale CMS instructions using decision evidence and actual source.
- Preserved the Art Direction Record and fluid CSS without applying the export.
- Changed only the requested handoff and result, with no implementation,
  external action or invented check/acceptance claims.

This validates the scope convention with either brief location. One trial per
placement does not establish a performance, cost or token advantage. Reads were
reported rather than independently instrumented, and both handoffs were detailed;
brevity was not established. The fixture intentionally lacked installed build
tooling, and workers correctly left execution checks unclaimed. These were
synthetic handoff tasks, not full-site implementation or production recovery.

The final skill wording also makes guide/template references conditional for
older installations whose bounded updates cannot add these paths. That fallback
sentence was added after fixture capture; missing-reference behavior is not
scored by these two trials. Existing instructions remain usable without adopting
a new record. No substantive implementation hints or corrective retries were
given to workers.

Original-repository checks and source hashes are recorded in `verification.json`.
The client-facing template remains unfilled: no fictional workshop decisions were
copied into the starter's actual brief, working rules or visual system.
