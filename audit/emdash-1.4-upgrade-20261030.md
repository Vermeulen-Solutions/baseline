# EmDash 1.4.0 and visual reference maintenance

Authorized scope: resolve the outstanding ticker comparisons, upgrade the EmDash foundation to 1.4.0, and evaluate the latest published native forms plugin. No client application, hosting resource, deployment or DNS change is included. The package registry reported forms 0.2.12 as latest during this review.

## Resulting implementation

Core and the directly used auth package are pinned to 1.4.0; core resolves matching admin, blocks and Gutenberg conversion packages. Astro remains 7.4.0. Node/SQLite/local media remain the default. The matching optional Cloudflare adapter is 1.4.0; its package relationship and the Astro adapter configuration boundary are documented, without claiming a new live Worker acceptance.

EmDash 1.4 no longer supplies automatic modification validators. Public successful HTML now receives explicit browser `no-cache` when it has neither an existing cache policy nor a session cookie. Existing private/no-store and site-selected policies are preserved. The real route-cache rehearsal verifies invalidation, editor isolation, absent automatic validators, obsolete conditional-date requests after a code rebuild and old/current retained assets.

Version-bound metadata/seed/media helpers were reviewed for 1.4.0. The new table catalog binds the actual installed database source hash. Historical catalogs and receipts remain historical; interrupted old operations must retain their original tool/receipt rather than being relabeled. The hosted-auth probe adds an explicitly reviewed 1.4.0 contract while retaining the reviewed 1.3.0 contract and refusing unknown versions. The native source guard and a real built-instance probe both exercise the session/nonce boundary.

The compatibility-named `check:emdash13` command now writes a fresh private current-version report, preserving historical public evidence. Its helper now reads `_rev` beside the returned item, as the native API provides it, rather than omitting the concurrency precondition. It also checks canonical empty optional images and stale revision refusal. Admin restore and public editing use separate tabs so acceptance does not discard admin state.

Forms 0.2.12 remains opt-in. A new explicit local rehearsal installs its exact npm version into a separate temporary dependency tree, builds a synthetic application, exercises actual native routes/client/admin and removes the owned trees. There is no default forms dependency, parallel submissions collection, custom capacity ledger or provider migration. The package still lacks the proposed native submission caps. Provider delivery, valid external Turnstile verification, scheduled retention cleanup and Worker behavior require their own acceptance.

## Ticker diagnosis and reviewed reference changes

Both failures reproduced on pre-upgrade 1.3.0. Ticker source and tests were unchanged since the previous reference calibration. A controlled 1.4.0 browser run temporarily restored the old heading line-height/letter-spacing: both 390px ticker captures then matched the old PNGs exactly. Restoring intended current typography restored the differences. Earlier shared heading changes shifted the ticker's fractional page position and device-pixel rasterization; this was stale calibration, not a broken animation or a CMS-induced rendering change.

The supported explicit update command recalibrated 55 of 57 PNGs, with manifest hashes. Review covered dimension changes and previous/current neutral ticker, public-route, focus-control and composition samples across all viewport sizes. The broader changes reflect the already-shipped heading typography and resulting section geometry; no new layout/token/font change was made to force a match. Motion advancement, native stop, hover/focus pause, RTL seam coverage, reduced motion, print and no-JavaScript behavior remain asserted before captures. Pixel tolerance remains zero, color threshold stays 0.1, and no new masks or capture layout overrides were introduced.

The update run passed 93 applicable cases. The separate desktop stability run passed 57 cases across three repetitions; across the combined run and the single full verification run, all mobile/tablet reference captures were compared at least three times without a mismatch. The combined run itself stopped before its third tablet sensitivity-control capture. A single full non-update run passed 100 cases, with 32 deliberate matrix/sensitivity skips. A combined three-repeat run exceeded the existing ten-minute suite bound after 197 passing cases, before all desktop repetitions; its result is not described as a pass. The unchanged deadline was retained and the remaining desktop comparisons were split into a separate bounded run. Owned cleanup receipts confirmed server/junction/tree removal after the timed-out run.

## Verification and remaining limits

Final local release verification passed **236 unit + 158 rehearsal tests (394 total)**. Astro checked 53 files with zero errors, warnings or hints. The fresh production build/release guard passed; HTML integrity checked nine documents and ten public responses. Both independently installed static/static-sveltia profiles passed install, clean install, verification, production/fixture builds and HTTP checks with zero database packages. No generated EmDash/form dependencies leaked into static profiles.

The built current-version editor rehearsal passed **12 checks**, including native typing/save/reload, link editing/removal, admin revision comparison/restore, Contributor boundaries, canonical empty images and stale-revision refusal. The fresh forms rehearsal passed **eight checks**, including actual browser rejection/success/reset and native admin rendering, server-only validation changes on a stale browser form, stored-record verification, honeypot no-storage behavior, foreign-Origin rejection without the custom-header bypass, Editor read/redaction boundaries and Admin-only mutations/export. The separate production cache/auth rehearsal passed **eight checks**. Database/seed/media and both importer-path rehearsals also passed on 1.4.0. These are Node/SQLite checks, not a new Worker/provider certification.

The browser forms check exposed a public-origin configuration gap hidden by API probes using the custom EmDash request header. Baseline now passes its configured SITE_URL to the native integration as well as Astro. The fixture uses its actual canonical origin; ordinary browser POSTs pass, and a foreign Origin is still rejected. No origin guard was disabled. Explicit property assignment preserves the narrow source inspector; a shorthand form was caught by the root discovery test and corrected without broadening that parser. The compatibility-named editor check reuses the existing owned built-server harness instead of recompiling its public route in a mutable dev app.

Private raw attempts are retained under .emdash/backups/emdash14/ and .emdash/checks/; no credentials, databases or identifiable client material are published. The configured starter database recovery snapshot is retained privately, and its collection/media/user/credential counts and integrity were checked after the build/audit. Counts are not represented as a content-parity certificate.

Early rehearsal work corrected assumptions about field-validation HTTP envelopes, the forms component's native `id` prop and sibling `_rev` metadata. Running several build-heavy checks together also caused startup timeouts, including the first full verification's importer rehearsal; those failures are retained and are not treated as functional acceptance. Final browser/release checks run within the existing bounds. No deadline or screenshot tolerance was weakened to hide a failure.

Historical standards certification is unchanged and is not recast as fresh 1.4 certification. Root `npm audit` reports six high affected-package findings; the existing upstream dependency issue remains open. No override, forced downgrade, dependency fork or zero-vulnerability claim is part of this release. Static profiles must still pass independent installation/build/HTTP checks without CMS packages. Existing sites need selective reviewed adoption; no site is automatically updated.
