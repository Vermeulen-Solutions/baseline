## Answer

**Mechanism: a container query, with the query container on an explicit wrapper around each card, not on the card itself and not on the grid.**

Why (from AGENTS.md routing to `astro-site-design` and its `references/responsive-architecture.md`):
- The skill's ladder is intrinsic CSS first, then a container query, then a media query. Intrinsic CSS (wrap, `auto-fit`) cannot do this job. Image-beside-text versus image-above-text is a switch between two distinct layouts, not a reflow.
- A media query is wrong because the available width follows placement, not the viewport. The reference describes this exact case: "the same card in a sidebar, grid cell, and full-width feature". At one viewport width the shop cell, the sidebar and the homepage band are all different widths.
- A card cannot query its own size to restyle itself. The query container must be an ancestor, and the reference recommends an explicit wrapper. For a list of cards, each item wrapper is the container, because querying the grid would measure the whole grid, not each cell.
- Do not use the `:has(> &)` auto-parent trick. It would mutate whatever parent the card lands in.
- Layout belongs to the structural component or wrapper, so I would add it to `Card.astro` / a ProductCard in `src/components/` and its layered CSS. I would not scatter overrides in the three page templates (docs/site-working-rules.md, Day-2 rules).

Markup. The wrapper is the container and the card is the thing that restyles. In the shop grid, make the `<li>` the wrapper:

```astro
<!-- ProductCard.astro -->
<div class="product-slot">
  <Card class="product-card">   {/* semantic <article class="card"> */}
    <div class="product-card__media"><ResponsiveImage ... /></div>
    <div class="product-card__body flow">
      <h3><a href="..." class="clickable-parent">...</a></h3>
      <p>...</p>
    </div>
  </Card>
</div>
```

For the shop list use `<ul class="cards"><li class="product-slot">...</li></ul>`, with `Grid` or the `auto-fit` columns for the three-column layout. The sidebar and the homepage band place the same component in a `Sidebar` / `Container` and need no per-context code.

CSS, in `@layer components`, using existing tokens and `:where()` for defaults:

```css
@layer components {
  .product-slot {
    container: product-slot / inline-size;
    min-inline-size: 0;           /* let it shrink in grid/flex tracks */
  }

  /* Default = narrow layout: image above text. Works with no container-query support. */
  .product-card {
    display: grid;
    gap: var(--card-gap, var(--spacing-content));
  }
  .product-card__media { min-inline-size: 0; }
  .product-card__media img { inline-size: 100%; block-size: auto; aspect-ratio: var(--product-ratio, 4 / 3); object-fit: cover; border-radius: var(--card-media-radius); }
  .product-card__body { min-inline-size: 0; overflow-wrap: anywhere; }

  /* Enough room: image beside text */
  @container product-slot (min-width: 32rem) {   /* example; tune against real content */
    .product-card {
      grid-template-columns: minmax(0, 2fr) minmax(0, 3fr);
      align-items: start;
    }
  }
}
```

Notes on the choices:
- The narrow layout is the base rule and the wide layout is added at `min-width`, so the fallback is readable without the feature.
- The container is named (`product-slot`), so a nested container cannot make the rule measure the wrong ancestor.
- It uses `container: name / inline-size`, not `size`, to avoid height containment.
- It uses `minmax(0, …)` and `min-inline-size: 0`, with no fixed heights, so long titles and variable content shrink instead of overflowing.
- Spacing uses `--card-gap`, `--card-padding` and `--spacing-content`. It does not combine a gap with flow margins for the same relationship. There are no arbitrary pixel values or breakpoint soup. The 32rem threshold is a starting value to set from where the real content stops working.
- Keep DOM order as image then text, with no `order` or `row-reverse`, so the source and keyboard order stay logical and RTL follows `dir`. The heading link keeps `.clickable-parent` and `.focus-parent`, so the whole card is clickable with a single focus ring.
- An image-beside-text card needs a matching `sizes` hint on the native Astro image for each context. Do not hand-write `sizes` from guesses.

Caveat: the three-column shop grid will often put each cell below 32rem, so the vertical layout will probably win there. The sidebar will too. Only the homepage band should go horizontal. Confirm this with measured widths, and move the threshold if the shop cells or the band land on the wrong side.

Before AGENTS.md's visual gates apply to real client work, the Art Direction Record must exist (`npm run check:art-direction -- --require-record`). This starter has none, so I would not call it done without one. Whether the gate applies to a local component adjustment is something I would confirm.

**What I would check before calling it done**
1. Mechanism and structure:
   - The container is on the wrapper, not on `.card` itself or on the grid.
   - Only one container is named and queried, and `inline-size` containment has not changed the wrapper's sizing in the real layouts.
   - All CSS is in `@layer components`, with no stray unlayered rules and no ID selectors or `!important`.
2. Rendered behavior in the three real placements:
   - The shop grid at its three-column width, the narrowest sidebar width, and the full-width band.
   - Intermediate widths around the mode change, so the card flips at the width the content needs.
   - The same card at the same viewport width in different slots, which proves the query follows the container and not the viewport.
3. Fallback: temporarily disable the `@container` rule and confirm the stacked layout is still readable and complete.
4. Unpredictable content:
   - Long titles, unbroken strings, long translated text and fewer or more cards.
   - A missing image and unusual image ratios.
   - RTL (logical properties, direction and reading order).
   - No fixed heights, and no clipping.
5. Accessibility and zoom:
   - 200% text resize and 400% zoom reflow, with no horizontal page scroll.
   - Keyboard focus visible, a single card-level ring, and focus order matching DOM order.
   - The heading link is the only link announced.
   - Alt text on the image.
   - Contrast on light and `data-surface="dark"` contexts.
6. Images: actual `sizes`/`srcset` selected per context against native dimensions, and above-the-fold images (the homepage band) loaded eagerly or with priority.
7. Project checks:
   - `/_styleguide` specimen of the card in narrow and wide slots, with notes in `audit/component-calibration.md`.
   - `npm run design:tokens` and `npm run test:design`.
   - `npm run verify`, `npm run build` and `npm run audit:html` against a fresh build.
   - Inspect the three real routes in a browser.
   - Report the checks actually run, and the acceptance limits for anything not run (for example, only one browser engine).
