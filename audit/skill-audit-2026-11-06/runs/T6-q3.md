## Answer

### Routing and gates
- AGENTS.md routes this to site work (not maintainer work), and to `astro-site-design` for implementation. `references/landing-page-archetypes.md` covers conversion sections, and its Subscription archetype is the right fit ("multi-tier pricing with monthly/yearly state").
- Before any site-specific visual work, the `## Art Direction Record` must be saved in AGENTS.md and `npm run check:art-direction -- --require-record` run. A pricing section is visual work, so I assume that gate is already passed. If not, I would do it first.
- Check `package.json` scripts and `baseline.config.json` before using any npm command. Static profiles do not need CMS tooling.
- Prices, uptime, customer count and response time are claims. The skill says never to invent evidence, so every number below is a placeholder (`{{...}}`) that must come from the owner or an approved source. If a metric cannot be sourced, omit that cell. If none can, omit the strip.

### Section order and geometry
The skill's default order is hero, then proof/telemetry strip, then later sections. It also forbids consecutive sections with the same geometry, so I avoid two stacked 3-column card grids:
1. Metrics strip: a 3-cell exposed `.grid-hairline` ledger. It is a ruled matrix, not shadowed cards.
2. Pricing: three tier cards with a billing switch, in a `Grid`. The strip is a hairline ledger and the tiers are surfaced cards, so the geometries differ. I would make the middle (featured) tier visually dominant so the row is not a flat 3x equal-card repeat. A `.bento-grid` 4/4/4 is the alternative, but `Grid` collapses more predictably here.
3. After pricing, vary the geometry again (for example a FAQ with `<Disclosure>`, then a closing `data-surface="dark" class="surface-spotlight"` band that repeats the primary CTA).

### Markup (`src/pages/index.astro` section, or a `PricingSection.astro` component fed by a data array)

```astro
---
import Section from '../components/Section.astro';
import Container from '../components/Container.astro';
import Grid from '../components/Grid.astro';

// Placeholders: every figure needs an owner-approved source before publishing.
const metrics = [
  { label: 'UPTIME (12 MO)', value: '{{99.9x%}}' },
  { label: 'CUSTOMERS', value: '{{N}}' },
  { label: 'MEDIAN RESPONSE', value: '{{N min}}' },
];
const tiers = [
  { id: 'starter', name: 'Starter', blurb: '{{who it is for}}', monthly: '{{€A}}', annual: '{{€a}}',
    features: ['{{feature}}', '{{feature}}', '{{feature}}'], cta: 'Start 14-day trial', href: '/signup?plan=starter' },
  { id: 'team', name: 'Team', blurb: '{{who it is for}}', monthly: '{{€B}}', annual: '{{€b}}', featured: true,
    features: ['{{everything in Starter}}', '{{feature}}', '{{feature}}'], cta: 'Start 14-day trial', href: '/signup?plan=team' },
  { id: 'enterprise', name: 'Enterprise', blurb: '{{who it is for}}', custom: 'Custom',
    features: ['{{everything in Team}}', '{{feature}}', '{{feature}}'], cta: 'Book architecture review', href: '/contact?topic=enterprise' },
];
---

<Section id="pricing" aria-labelledby="pricing-title" class="section-defer">
  <Container width="wide">
    <p class="eyebrow-telemetry">[02 // PRICING]</p>
    <h2 id="pricing-title">Plans that scale with <em class="font-accent">your team</em></h2>
    <p>{{one or two sentences: what the plans include and who they serve}}</p>

    <!-- 1. Metrics strip: ledger geometry, tabular figures -->
    <dl class="grid-hairline" aria-label="Service metrics">
      {metrics.map((m) => (
        <div>
          <dt class="eyebrow-telemetry">{m.label}</dt>
          <dd class="tabular-nums">{m.value}</dd>
        </div>
      ))}
    </dl>

    <!-- 2. Pricing island: billing state lives on this root -->
    <div class="pricing" data-pricing data-billing="monthly">
      <div class="pricing__switch" role="group" aria-label="Billing period">
        <button type="button" class="badge-pill" data-billing-btn="monthly" aria-pressed="true">Monthly</button>
        <button type="button" class="badge-pill" data-billing-btn="annual" aria-pressed="false">
          Annual <span class="eyebrow-telemetry">{{save N%}}</span>
        </button>
      </div>
      <p class="visually-hidden" role="status" aria-live="polite" data-billing-status></p>

      <Grid minimum="standard">
        {tiers.map((t) => (
          <article class:list={['pricing-card', 'flow', t.featured && 'surface-elevated']} data-featured={t.featured ? '' : undefined}>
            <header class="flow">
              <h3>{t.name}{' '}{t.featured && <span class="badge-pill">Most chosen</span>}</h3>
              <p>{t.blurb}</p>
            </header>

            {t.custom ? (
              <p class="pricing-card__price tabular-nums">{t.custom}</p>
            ) : (
              <p class="pricing-card__price tabular-nums">
                <span data-price="monthly">{t.monthly}<small> / month</small></span>
                <span data-price="annual" hidden>{t.annual}<small> / month, billed annually</small></span>
              </p>
            )}

            <ul class="flow">
              {t.features.map((f) => <li>{f}</li>)}
            </ul>

            <a class:list={['btn', !t.featured && 'btn--secondary']} href={t.href}>
              {t.cta} <span aria-hidden="true" class="icon-nudge">→</span>
            </a>
          </article>
        ))}
      </Grid>
    </div>
  </Container>
</Section>
```

Notes on the markup:
- The metrics `dl` carries `.grid-hairline`. Cells that look like a ledger but are semantically term/value pairs are better as a `dl` than as bare divs.
- Hairline cell internals should use `.eyebrow-telemetry` for labels and `.tabular-nums` for figures, as the skill requires for all metrics.
- Astro v7 `compressHTML: 'jsx'` strips newline whitespace between inline elements, so the badge next to the tier name uses an explicit `{' '}`. Keep inline spans on one line.
- Both prices are in the HTML. Without JS, the monthly price shows and the annual `hidden` span is not shown. The annual price is then missing for no-JS users, so I would also add a plain-text line ("or {{€a}} / month billed annually") inside a `<noscript>` or as small print. This keeps content available as progressive enhancement.
- CTAs: active verb plus concrete outcome. The skill bans "Get Started" and "Submit". The same primary label repeats across tiers and the hero/closing band. Enterprise uses a different, honest next step. Do not add "No credit card required" or "Cancel anytime" unless the real terms say so.

### JS (zero-framework micro-island)
Per landing-page-archetypes section 9, bind on `astro:page-load` (not `DOMContentLoaded`) and guard against double binding, because `ClientRouter` may be in use.

```astro
<script is:inline>
  const bindPricing = () => {
    document.querySelectorAll('[data-pricing]').forEach((root) => {
      if (root.dataset.bound === 'true') return;
      root.dataset.bound = 'true';
      const status = root.querySelector('[data-billing-status]');
      root.addEventListener('click', (e) => {
        const btn = e.target instanceof Element ? e.target.closest('[data-billing-btn]') : null;
        if (!btn) return;
        const mode = btn.getAttribute('data-billing-btn');
        root.dataset.billing = mode;
        root.querySelectorAll('[data-billing-btn]').forEach((b) => b.setAttribute('aria-pressed', String(b === btn)));
        root.querySelectorAll('[data-price="annual"]').forEach((el) => { el.hidden = mode !== 'annual'; });
        root.querySelectorAll('[data-price="monthly"]').forEach((el) => { el.hidden = mode === 'annual'; });
        if (status) status.textContent = mode === 'annual' ? 'Showing annual billing prices' : 'Showing monthly billing prices';
      });
    });
  };
  bindPricing();
  document.addEventListener('astro:page-load', bindPricing);
</script>
```

The script is inline and uses no framework. If prices come from the frontmatter data, `define:vars` is available, but the DOM already holds both values, so it is not needed.

### Existing Baseline utilities chosen, and why
| Utility | Where | Why |
| --- | --- | --- |
| `Section`, `Container width="wide"` | outer structure | Section owns vertical padding and Container owns gutters and content gap, so no extra spacing wrappers (spacing ownership rule). |
| `Grid minimum="standard"` | tier cards | Grid owns the grid gap. Responsive auto-fit columns avoid a hand-written media query. The skill also says to check awkward last rows with 3 items. |
| `.grid-hairline` | metrics strip | The skill's named pattern for a 3 to 4 cell proof ledger. It is a different geometry from the cards below, avoiding consecutive identical card grids. |
| `.eyebrow-telemetry`, `.tabular-nums` | labels and all numbers | Required for metrics and counters. The mono voice is also visible above the fold of the section. Figures do not jitter when the price swaps. |
| `.font-accent` in the heading | one or two focal words | The 4-voice typography rule. Used on the h2 only, kept inline on one line. |
| `.badge-pill` | billing buttons, "Most chosen" | The existing pill control, and the same `aria-pressed` pattern as the `data-filter-btn` toolbar. |
| `.surface-elevated`, `--color-surface`, `--color-border(-strong)`, `--surface-highlight` | tier cards | 3-tier surface depth. The featured tier is raised, so hierarchy comes from surface and not decoration. |
| `.btn`, `.btn--secondary`, `.icon-nudge` | per-tier CTA | Tactile action hierarchy: primary for the featured/main plan, secondary for the others. The trailing arrow gets the spring hover. |
| `.flow` | text stacks inside cards | Flow spacing for text siblings only. I avoid also adding gaps for the same relationship. |
| `.section-defer` | whole section | Below-the-fold sections get `content-visibility: auto`. Remove it if the section sits above the fold. |
| `data-reveal` (optional) | cards | Progressive scroll reveal, which is fully visible without JS. Only if it serves a visitor need. |

### Utilities considered and rejected
- `Card.astro` with `.clickable-parent`: its contract is a heading link that stretches over the whole card. A pricing card has a deliberate CTA button, and a stretched link would compete with it and mislead on what the click does. So I use a dedicated `.pricing-card` article that borrows the same tokens and surfaces.
- `data-filter-root` / `data-filter-btn` / `data-filter-item`: it already toggles `aria-pressed` with zero JS, but it hides and shows whole items and replays `.animate-card-in` on cards. I need to swap one price inside every card and announce it, so a small dedicated island is cleaner.
- `.stack-cards`, `.bento-grid`, `.reel-snap`: not needed for three tiers. `.bento-grid` is a fallback if I want an 8/4 split with an enterprise sidebar.
- `LogoTicker`: a good proof component, but the request is for metrics, and the skill offers it only when publishable logos exist.
- `.ui-specimen` + `.viz-bars`: could dress up the metrics (a live-coded B2B specimen), but fake telemetry would break the truthfulness rule unless the data is real.
- A React/Svelte toggle: the skill says to avoid client frameworks for this kind of widget.

### Accessibility and acceptance
- The billing switch is a group of two `aria-pressed` buttons (matching the skill's own pattern) with a polite status message. The alternative, `role="switch"` with `aria-checked`, also works but needs a visible label on both states.
- Keyboard: buttons and links are natively focusable, and `:focus-visible` is provided by the primitives. Target size is at least 24px.
- Contrast: check `.badge-pill` and `small` text in both surface modes (daylight/dark), especially the faded `opacity` small print.
- Motion: price animation only under `prefers-reduced-motion: no-preference`.
- Do not claim conformance from automated checks alone. Manual keyboard and screen-reader check against `references/screen-reader-checks.md` if reader output is required.
- Responsive check at 375, 768 and 1440 px for overflow, clipped text, wrapped price lines (for example "/ month, billed annually"), and the CTA alignment across cards of different content length.
- Because this adds client-side script, AGENTS.md requires a headless Chromium run on the built route with `pageerror`/`console.error` listeners, including rapid repeated toggle clicks and navigating away and back (BFCache, `astro:page-load` rebinding).
- Then follow the site's verify sequence (`npm run verify:fast`, `verify`, `build`, `audit:html`), only for commands that exist in `package.json`.
- Honest limits: I have not rendered this; the token names and component props (`Grid minimum`, `Section` attributes) are taken from the skill text and need checking against the actual source.
