## Answer

Routing: AGENTS.md says this is site work (scoped change to an existing page). The task is presentation, so I used `astro-site-design`, and within it `references/baseline-utilities.md` and `references/landing-page-archetypes.md`. Pricing with a billing toggle is the "Subscription" archetype: trust strip, plan cards with a billing toggle, FAQ. Caveats: the site source is not included, so the Art Direction Record, `package.json` scripts and the installed `global.css` were not checked. The real site must have a saved Art Direction Record and pass `npm run check:art-direction -- --require-record` before this visual work. Check that each utility below exists in the installed `global.css`.

Content rule: prices, uptime, customer count and response time are placeholders marked `TODO`. Landing-page-archetypes says claims, prices and results need evidence, so none are invented. The metrics strip is omitted if no verified numbers exist.

### Utilities chosen and why

| Need | Utility | Why |
| --- | --- | --- |
| Metrics strip (uptime, customers, response time) | `.grid-hairline` with `.tabular-nums` figures and `.eyebrow-telemetry` labels | The archetype file prescribes a `.grid-hairline` metric ledger for verified numbers. Tabular figures stop digits shifting width. It is a different geometry from the 3-card row below, so no two consecutive sections share a layout. |
| Section and width | `<Section>`, `<Container width="wide">`, `<Grid minimum="standard">` | These primitives own padding and gaps under the shipped spacing hierarchy. I add no manual margins or `gap-7`-style values. |
| Plan cards | `<Card>` (`<article class="card">`) with a `data-featured` variant that uses `.surface-elevated` | Card is the reusable primitive. The elevated surface gives depth from tokens, not hand-picked greys. I drop the Card link, because the CTA is a `.btn`. |
| CTAs | `.btn` for the recommended tier, `.btn--secondary` for the others, with `.icon-nudge` arrows | This is the site's action hierarchy: one primary action plus secondary ones. Labels name the outcome ("Start 14-day trial"), not "Get started". |
| Billing switch | Native `<button role="switch">` plus a small micro-island script | This follows the micro-island guidance: `define:vars` script, bound on `astro:page-load`, no framework. A button is keyboard operable by default. The default HTML shows monthly prices and works without JS. |
| Heading voices | `--font-display` heading, `.font-accent` on one word, `.eyebrow-telemetry` tag | These are the four typography roles. |
| Optional | `data-reveal` on the cards | Scroll reveals are progressive enhancement. I'd add them only if the brief wants motion. I skipped `.ui-specimen`, `.stack-cards` and `data-filter-*` because there is no visitor need for them here. |

Placement: metrics strip first, then the pricing section, per the default build order (proof strip, then the argument). The sections before and after should not be 3-column card grids. If the feature section above is one, make this one distinct, for example by giving the featured plan a wider bento span.

              <a class:list={['btn', !t.featured && 'btn--secondary']} href={t.href}>
                {t.cta} <span aria-hidden="true" class="icon-nudge">→</span>
              </a>
            </div>
          </Card>
        ))}
      </Grid>
    </div>
  </Container>
</Section>

<script is:inline define:vars={{ labels: { monthly: 'monthly', annual: 'annual' } }}>
  const bindBilling = () => {
    const root = document.querySelector('[data-billing-root]');
    if (!root || root.dataset.bound === 'true') return;
    root.dataset.bound = 'true';
    const sw = root.querySelector('[data-billing-switch]');
    const apply = (period) => {
      const annual = period === 'annual';
      root.dataset.period = period;
      sw.setAttribute('aria-checked', String(annual));
      root.querySelectorAll('[data-price-monthly]').forEach((el) => (el.hidden = annual));
      root.querySelectorAll('[data-price-annual], [data-price-annual-note]').forEach((el) => (el.hidden = !annual));
    };
    sw.addEventListener('click', () => apply(root.dataset.period === 'annual' ? 'monthly' : 'annual'));
    apply('monthly');
  };
  bindBilling();
  document.addEventListener('astro:page-load', bindBilling);
</script>
```

Notes on the markup:
- `{' '}` separates the price figure from the unit text. This avoids the Astro v7 `compressHTML: 'jsx'` newline stripping that would otherwise concatenate the words.
- Both prices are in the HTML, so the content is crawlable. With no JS, monthly shows and annual stays hidden. The CTA links work either way.
- `aria-live="polite"` on the price paragraph announces the change when the switch is toggled.
- The switch is bound on `astro:page-load` with a `data-bound` guard, so it survives `<ClientRouter>` navigations and is not double-bound.

```

Token names (`--color-action`, `--color-text-muted`, `--text-step-*`, `--ease-smooth`) are assumed from the skill text and must be checked against the installed `global.css`. Card and Grid props such as `class:list` and `data-featured` also depend on the installed components. If a component does not pass attributes through, wrap it in a div.

### Verification to run before handoff
- Use the site's `package.json` scripts, not Baseline tooling it lacks: `npm run verify:fast` while editing, then `verify`, `build` and `audit:html`.
- Because this adds client script, launch headless Chromium and listen to `pageerror` and `console.error`. Probe rapid double-clicks on the switch and navigation away and back through `<ClientRouter>`.
- Check keyboard (Tab, Space or Enter on the switch), the screen-reader name and state, and reduced motion.
- Check zero horizontal overflow at 375, 768 and 1440 px, and a long tier name with translated French text. The site is French-first, so labels, currency format and "par utilisateur / mois" need French copy.
