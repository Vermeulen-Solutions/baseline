# Standards 0.5.1 — Fixes from the design rollout

Reviewed 2026-11-18. Standards tag: `standards-v0.5.1`.

A patch on 0.5.0: what taking the visible 0.3.0–0.5.0 changes on six built sites found.

- `check:quality` no longer reports controls off screen on smooth-scrolling pages.
- Page titles add the site name only when the result fits 60 characters.
- `npm run icons -- --opaque` keeps a light mark visible.
- Six shared components gate their hover effects.
- `sync:baseline` ignores imports in comments.
- The token tests pass on sites with their own palette.
- The update guide records what the rollout taught.

Runtime and development dependencies and the database schema are unchanged from 0.5.0.

Certified source: commit `377e9a856432531bc96acb2008e0a8ebe0fc7237`. Evidence: [verification-0.5.1.json](../../audit/certification-2026-11-18/verification-0.5.1.json) and the certification README.

## Changes for sites

10 change notes; the largest is a patch change. Each entry says which platforms it affects and how a site takes it.

### Changes how pages look: decide per site

#### Page titles add the site name only when it fits

_EmDash and static · components · Review and merge by hand; a decision per site · files: `src/layouts/Base.astro`, `profiles/static/project/src/lib/metadata.ts`_

The Base layouts (and the static profile's metadata) added " — Site name" to every page title, so a descriptive title went past the 60 characters search results show and `check:quality` reported `title`. The site name is now added only when the whole title stays within 60 characters; a longer page title stands alone, and the name is still in `og:site_name`.

##### For sites

Base and the static metadata are site-owned, so merge by hand: build the branded title, and use it only when it is 60 characters or fewer. Titles over 60 characters that come from editor content (an SEO title field) stay an editor decision.

### Copy into the site

#### Hover effects in shared components only where a pointer can hover

_EmDash and static · components · Copy the named files into the site · files: `src/components/Card.astro`, `src/components/CopyButton.astro`, `src/components/PhotoGallery.astro`, `src/components/SearchDialog.astro`, `src/components/TableOfContents.astro`, `src/components/Tabs.astro`_

`global.css` gated its hover styles in 0.4.0, but six shared components still had bare `:hover` rules, so a tapped tab, copy button, search result, table-of-contents link or gallery image kept its hover look on touch screens. Those rules now sit behind `@media (hover: hover)`. Rules that pair hover with focus are unchanged, and nothing changes with a mouse.

##### For sites

Unedited copies arrive with `npm run site:files -- --site <path> --apply` (static sites: `sync:baseline`). Sites that edited a component gate its hover-only rules the same way.

#### check:quality no longer reports controls off screen on smooth-scrolling pages

_EmDash and static · tooling · Copy the named files into the site · files: `scripts/check-quality.mjs`_

On a page with `html { scroll-behavior: smooth }`, a browser scrolls the control reached with Tab into view over a few hundred milliseconds. `check:quality` measured straight after the key press, so every control below the first screen was reported as `focus-obscured` ("off screen"): over 60 false findings on one site. The check now scrolls at once while it tabs. The page keeps its own setting for visitors.

##### For sites

Copy `scripts/check-quality.mjs` with the next helper update. Rerun `check:quality`; the remaining `focus-obscured` findings are real.

#### App icons for light marks, and a portable icon test

_EmDash and static · tooling · Copy the named files into the site · files: `scripts/generate-icons.mjs`, `tests/generate-icons.test.mjs`_

- **`npm run icons -- --opaque`** puts `icon-192.png` and `icon-512.png` on the ground colour too, padded by `--padding`. Without it they stay transparent, so a white logo was invisible on a light launcher.
- **The icon test is portable.** It looks for the touch icon and manifest links in Base or SiteShell. A site that links them from SiteShell no longer fails it.

##### For sites

Copy both files. A site with a light mark reruns `npm run icons -- --source <mark> --background "<ground>" --opaque` and commits the PNGs.

#### sync:baseline ignores imports in comments

_static · tooling · Copy the named files into the site · files: `scripts/sync-baseline.mjs`_

The static sync's import preflight read a JSDoc type such as `{import('./x.mjs').Options}` as a real import and refused an otherwise clean update of `scripts/baseline-features-integration.mjs`. It now removes comments before scanning. `//` after a colon, as in a URL, is not treated as a comment.

##### For sites

Copy `scripts/sync-baseline.mjs` before the next sync.

#### Token tests pass on a site with its own palette

_EmDash and static · tooling · Copy the named files into the site · files: `tests/fluid-tokens.test.mjs`, `tests/token-contract.test.mjs`_

0.5.0 limited the exact-value token checks to stylesheets without the strict theme. A site with its own palette but no strict theme still failed: it was held to the starter's page colour, spacing scale and motion tokens. The exact values are now checked only on the untouched starter stylesheet, recognised by its page colour. Any other stylesheet is checked for its shapes: a typed oklch page colour and the spacing token names.

##### For sites

Copy `tests/fluid-tokens.test.mjs` and `tests/token-contract.test.mjs` when the site has not edited them (`npm run site:files -- --site <path>` from Baseline says so).
