# Standards 0.8.0 — EmDash 1.6 and the look pass

Reviewed 2026-11-24. Standards tag: `standards-v0.8.0`.

EmDash 1.6.0, and what the design rounds after 0.7.0 changed in how Baseline looks at a built page (PRs #160–#178).

- **EmDash 1.6.0.** One database migration (`098_user_last_login`), Kumo 2.19.0 and Forms 0.2.14. The starter's pages set the cache hint before a 404 and read menus and terms in the page's locale. Follow the [1.6 upgrade guide](../../docs/emdash-1.6-upgrade.md) and run the media usage repair once after the deploy.
- **A look pass.** Every screen of a built page in one pass, one line each, and a score; it covers long pages to their real foot.
- **The composition audit reads more like a designer.** It is checked against designers' votes, reads whether text can be read, finds a label struck through by a drawn part, and allows an earned label above a heading and an accented phrase.
- **A motion tier in the record**, and a site's world comes from sources rather than a list of devices.
- **A site can be started by one model and built out by another.**
- **Fixes:** `hidden` always hides, PhotoSet takes any number of photographs, the phone header's two-line clamp applies to a plain text title only (visible), `media:prepare` explains its arguments, and `verify` stays green in a site with its own typeface.

Runtime dependencies: EmDash and `@emdash-cms/auth` move from 1.5.0 to 1.6.0; Astro 7.4.12 and the adapters are unchanged. The database schema gains one column.

### Changes how pages look: decide per site

#### The phone header's two-line clamp applies to a plain text title only

_EmDash and static · styles · Review and merge by hand; a decision per site_

Below 48rem the starter clamps a text site title to two lines. The rule matched every brand link without a logo image and outweighed a site's own brand class, so a brand built from elements (a mark beside the name, the name and a place) was laid out as the clamp's stacked box: in two design sprints the name ran into its divider, or the mark sat above the name.

- The clamp now applies only to a brand link that holds plain text, and it carries the weight of the `.site-brand` class alone, so a site's own brand class can replace it.
- A plain text title and a logo image behave as before.

##### For sites

Sites own `src/styles/global.css`: replace the selector of the rule inside `@media not (min-width: 48rem)` that sets `-webkit-line-clamp: 2` with `:where(.site-nav:has(> .site-menu)) > .site-brand:where(:not(:has(> *)))`. Only a site whose brand link contains elements other than a logo image looks different on a phone: its brand keeps the layout the site gave it. Check the header at 390 once, and remove any override the site added to defeat the old rule.

### Review and merge by hand

#### The `hidden` attribute always hides

_EmDash and static · styles · Review and merge by hand; a decision per site_

A piece that sets its own `display` (a row laid out as a grid, a flex list item) stayed on screen when a script gave it the `hidden` attribute, because an author rule outweighs the browser's own rule for `hidden`. A programme filter built in a trial could not hide its rows until a rule was added by hand.

The starter's base layer now opens with:

```css
[hidden]:not([hidden="until-found"]) {
	display: none !important;
}
```

`hidden="until-found"` is left to the browser. Nothing the starter shows changes: its own components already hid what they marked hidden.

##### For sites

Sites own `src/styles/global.css`: add the rule at the top of `@layer base`. Before adding it, search the site for a rule that deliberately shows an element carrying `hidden`; none is expected, and such an element should lose the attribute instead.

### Copy into the site

#### A label struck through by a drawn part is found

_EmDash and static · skills, tooling, docs · Copy the named files into the site · files: `scripts/audit-composition.mjs`, `tests/audit-composition.test.mjs`_

Four trial sites were built with the look pass and the three new legibility findings, each followed by a fresh session that looked at every screen. All four passed with no legibility finding. One of them, at 1440px, carried five service labels each crossed in its middle by the drawn stem of the valve above it, with one letter of each gone. Nothing saw it: `text-covered` read a hidden run from one end of a line only; the builder's look lines and the fresh session both read "none" for that screen.

- **`text-covered`** now also reads each letter and digit of a line (type under 72px). A letter that changes next to nothing in its own box between the page as painted and the page with its text unpainted, while most of the line's letters show, is a candidate; so are two neighbours that are each mostly unchanged. As before, it counts when something else than the line's own element lies on top at that point, and a bar that rides over the page is not a cover. The finding names the line and says "1 letter inside the line".
- The message adds: a drawn part (a stem, a needle, a rule) passes beside a label, never through it. `world-building.md` gives the fix.

Evidence: the read finds all five labels on that site. On the twenty other trial sites still built it adds two places, both seen by eye and both real: a strip of drawn tape over the first words of a caption, and a card over a line of the block above. Twelve public professional home pages give one: a round sticker that floats over a grid of cards hides the ends of four lines on the phone.

#### The craft pass can be followed as written, and the look tool reads its routes on Windows

_EmDash and static · skills, tooling · Copy the named files into the site · files: `scripts/design-look.mjs`, `tests/design-look.test.mjs`_

Baseline's craft pass (critique, the refine commands, polish) was run for the first time on three trial sites, by two models. All three runs found real faults and fixed them, and all three stumbled on the same places in the pass itself.

- **`polish` is a procedure, not a command.** `impeccable-passes.md` said to "run `polish <page source>`"; the launcher has no such command. The pass now says to follow `polish.md`.
- **The snapshot is read before the first fix.** The helper fingerprints the page's source file, so after the first edit `critique-storage latest` and `close` exit 2 and the backlog is closed by the helper. The pass now says to read the snapshot once before fixing, to work from that body, and that exit 2 afterwards is the expected end.
- **Three things a job needs and the references do not say:** the overlay's live server takes `--port`; the context loader's closing-sentence directive belongs to an interactive session; and a page with a pinned scene or an arrival is also looked at once with motion allowed, because the capture tools take their pictures with motion reduced.
- **`design:look` puts a route back** when Git Bash has rewritten `/` or `/about` into a path under its install folder, as the other capture tools already do. One run captured the wrong page and overwrote its look file.

Not fixed here: inside a site whose tokens have been changed, two of the starter's own spacing-token tests fail, so `npm run verify` is red before any edit.

#### Design checks: motion names, unloaded pictures, and the first-screen checks at Stage 5

_EmDash and static · tooling, skills, docs · Copy the named files into the site · files: `scripts/check-art-direction.mjs`, `scripts/audit-composition.mjs`, `scripts/check-quality.mjs`, `tests/world-record.test.mjs`, `tests/audit-composition.test.mjs`, `tests/check-quality.test.mjs`_

Seven design sprints on a frozen release met three faults in the design checks.

- **Motion names.** `check:art-direction` read every backticked word on the record's World › Motion line as an animation the site promises, so a record that also named its page-transition style, `data-arrive` or the scroll library failed `audit:composition` on `world-motion` for an animation nobody promised (five of seven runs). A motion is now a backticked name followed by a colon or a bracket and what it belongs to (`stamp-lands`: the stamp on the label); when the line uses that form, only those names count. The starter's own words (`fade`, `lift`, `curtain`, `wipe`, `data-arrive`, `Lenis`, `prefers-reduced-motion` and similar) are never counted. A line that only lists names with commas is read as before.
- **Unloaded pictures.** `audit:composition` measured a page before every lazy picture had loaded, then read the picture's `src` attribute, the small fallback beside its srcset, and reported `soft-photo` for a full-width photograph the browser shows from a large file. It now brings each pending picture into view and waits for it, and a picture with a srcset counts only by the file the browser chose.
- **First-screen checks at Stage 5.** Three of seven runs finished with a scroll-driven entrance caught part-way on the first screen, which reviewers saw as a crooked card at load; `check:quality` reports it, but only at Stage 6. `check:quality -- --only <kind,kind>` reports the named kinds and nothing else, and the Stage 5 comparison pass now runs `--only first-viewport-hidden,first-viewport-scroll-motion` on the served build before a page is called finished.

##### For sites

Copy the files. Nothing changes on a built site. A record whose Motion line names a starter word in the described form (`lift`: between pages) no longer counts it towards the three motions the gate asks for: name the world's own animations. The Stage 5 step arrives with the usual skill sync.

#### Impression scenes must carry the subject; faster audits; fixes from four more design sprints

_EmDash and static · skills, tooling, docs · Copy the named files into the site · files: `scripts/audit-composition.mjs`, `scripts/capture-routes.mjs`, `scripts/design-sheet.mjs`, `tests/audit-composition.test.mjs`, `tests/design-sheet.test.mjs`_

Four design sprints tested the motion tier with a weaker agent. All four chose the right tier from the client's words, and the three impression sites built a smoothed scroll, page transitions and a pinned scene. They also showed what the first version left open.

- **A scene must carry the subject.** Two sites built from one brief both passed: one told the club's night through five full-screen photographs (58% of the screen changes through the scene), the other turned one clock hand beside three lines of text (0.2%). `audit:composition` now takes frames near the start, middle and end of the first pinned scene and reports `impression-motion` when less than a quarter of the screen changes. The impression reference says what a scene shows and gives the two cases.
- **The impression reference reaches generated sites.** A static site's `AGENTS.md` pointed at `astro-site-design/references/impression-motion.md`, which the profile did not install.
- **The motion tier is narrower.** A client who asks only that the site be inviting or show the atmosphere is `editorial`; `impression` needs a request for impact or movement, or a club, a concert or event venue, a festival, or a studio or artist showing visual work.
- **A motion that plays once at load has run.** `world-motion` counted animations only while scrolling, so an arrival was reported as never run and sites turned their arrivals into scroll-driven entrances to pass. Animation starts are now recorded from the first paint.
- **Audits are faster.** With `--references`, each reference's live page is measured once and kept in `reference-measures.json` beside the references file (57 seconds a pass became 10); `--refresh-references` measures again.
- **`capture:routes`** waits four seconds at most for an image to decode (a lazy image with `sizes="auto, …"` held a route until its three-minute timeout), and `OVERFLOW-X` names the element that reaches furthest past the edge.
- **`design:sheet`** accepts a single image, as the Stage 5 step that asks for a page-only sheet needs.
- World building says an arrival starts visible, which the first-screen check already required.

##### For sites

Copy the files; the guidance arrives with the usual skill sync. An impression site whose pinned scene changes less than a quarter of the screen now fails `audit:composition` until the scene shows the site's photographs or content at stage size. A site whose record says `impression` only because the client asked for atmosphere may record `editorial` and remove the three pieces, or keep them.

#### The composition audit is checked against designers' votes

_EmDash and static · skills, tooling · Copy the named files into the site · files: `scripts/audit-composition.mjs`, `scripts/check-art-direction.mjs`, `tests/audit-composition.test.mjs`, `tests/world-record.test.mjs`_

Baseline's measures were run on 95 public pages that professional designers had ranked in blind pairs: six briefs, each with a page made by a designer and fifteen generated ones. Most measures move with the votes (rotated or masked objects, type sizes, drawn objects, elements). Three things did not hold up, and two habits turned out to mark generated pages.

- **The number of type voices is no longer counted.** It did not move with the votes, and four of the six designer-made pages had fewer than three. `bare-page` now reports when three or more of four things are missing (a surface, drawn objects, depth, motion). World building asks for two voices and a third only when a picture shows the world lettering its small things another way: a third voice added because a rule asked for one is how a mono label ended up over every heading of the trial sites.
- **A small label above three or more section headings** (`kicker-openings`) was on none of the designer-made pages and on every one of the best-ranked generated pages. It is a floor finding for a direction whose record has a `Sources` line and stays an advisory on older sites.
- **One italic word in an upright page heading** (`accent-word`, new) was on none of the designer-made pages and on a third of the best generated ones. It is a floor finding under the same rule. The skills no longer recommend the italic accent for a new direction; the `.font-accent` class stays for sites that use it.

Four sites built with sources then showed three more things, each now checked.

- **The label rule sees a label in any dress.** A line of a few words under half the heading's size counts in lower case or a handwritten face too: one site wrote five chalk labels above five headings and passed. The wider rule gives the same shares on the 95 pages (none of the designer-made, all of the best generated).
- **One line of text lying over another** (`text-collision`, new) is a floor finding for a direction with a `Sources` line: at the wide width, on a phone and at three depths of a pinned scene. Faint text, a fixed header, a turned object, text on a path and words printed twice in one place are left out; on 43 earlier trial sites it reports five places.
- **A third type voice is chosen from a specimen sheet** like the display face, or left out. `check:art-direction` reports a `Utility`, `Mono`, `Labels` or `Third` face in the Typography Pairing that is on no sheet in `audit/world/faces.md`. Three of four sites had added the same mono face from memory.

##### For sites

Copy the files; the guidance arrives with the usual skill sync. A site whose record has no `Sources` line sees the two findings as advisories. A direction made with sources removes the labels above its headings, sets its page heading in one style and gives every line of text its own space before `audit:composition` passes, and puts a third voice on a specimen sheet before `check:art-direction` does.

#### A label above a heading and an accented phrase are allowed when earned

_EmDash and static · skills, tooling · Copy the named files into the site · files: `scripts/audit-composition.mjs`, `tests/audit-composition.test.mjs`_

The composition audit failed a sourced direction for three or more small labels above section headings, and for one italic word in the page heading, whatever they said. The owner's preferred references use both, and use them well. The two findings now report only the unearned use.

- **`kicker-openings`** counts the labels that only name their section. A label that carries a fact the visitor needs (a date, an hour, a price, a count, a distance) is earned and not counted. The audit reads a figure or a currency in the label, after setting aside a bare index at its start (`01 //`, `[02]`, `03 ·`): a bare number is not a fact. Three or more unearned labels are the finding, as before.
- **`accent-word`** reports a word or phrase in italics in some headings and not others. It is earned once, in the page heading, or as the direction's way of setting every heading (four in five or more), which the Art Direction Record names.
- The skills say the same: `site-art-direction` (the accent, the lanes, world building), `astro-site-design` (the typography roles and the list of generated-page marks) and the craft-floor exceptions in `impeccable-passes.md`.

Checked on three public pages that use both devices throughout and on two trial sites: an italic word carried through every heading is no longer reported; labels that only name their section still are (six to nine a page); the trial sites are unchanged.

##### For sites

Copy `scripts/audit-composition.mjs` and the skills. A site that removed fact-bearing labels or its page heading's accent to pass the audit may put them back.

#### The composition audit reads whether the text can be read

_EmDash and static · skills, tooling · Copy the named files into the site · files: `scripts/audit-composition.mjs`, `tests/audit-composition.test.mjs`_

Nine trial sites from three rounds were scored by eye on six questions (does the look come from the client's own thing, is there a feature that does the visitor's job, can it be done on a phone, craft, the made things, one idea carried through). Craft was the lowest question in every round, and what cost the points was nearly always text: date cards a few letters wide on a phone, a ticket wider than the phone, a plan whose labels came out at 5px, a caption in white script over white flowers. The agents that built these sites looked at their own screenshots fifteen to thirty-eight times a run and shipped these faults all the same, so the audit names them.

`audit:composition` now reads four more things from the lines of text on the page, at the wide and at the narrow width:

- **`text-cut`:** a line cut off by a frame or by the edge of the screen: a tenth of its width or more, while part of it shows. A strip made to move sideways, an ellipsis and a word set over 72px (which may bleed off the page on purpose) are left out.
- **`text-squeezed`:** one run of text, up to 32px, wrapped onto three lines or more with under eight characters a line. Lines broken on purpose are separate runs and do not count.
- **`text-tiny`:** text of three letters or more painted under 9px, counting the scale of the drawing it sits in.
- **`text-unreadable`:** a line that cannot be told from the picture behind it. The page is photographed with its text unpainted, once with the letters' shadows and once without, and each line's colour is held against what is behind its box. A line counts when it would stand out by less than 2 to 1 (type of 24px and more) or 3 to 1 over 30% of its box in both pictures, and the ground is a picture. A flat ground stays with the contrast check in `audit:ui`.

All four are floor findings for a direction whose record has a `Sources` line and advisories on older sites, like `text-collision`. Text in a turned object (a stamp, a card set at an angle) now counts for the size and the width measures and is still left out of the collisions.

World building says what usually causes each one in a built world and where its fix is: in the object, not in the words.

##### For sites

Copy the two files; the guidance arrives with the usual skill sync. A direction made with sources makes every line readable at both widths before `audit:composition` passes. The audit takes three full-page screenshots more per route and width.

#### The look covers a long page to its foot, the browser tools find a site under either local name, and Disclosure can be restyled

_EmDash and static · tooling, components · Copy the named files into the site · files: `scripts/design-look.mjs`, `scripts/capture-routes.mjs`, `scripts/audit-composition.mjs`, `scripts/audit-ui.mjs`, `scripts/check-quality.mjs`, `scripts/record-motion.mjs`, `src/components/Disclosure.astro`, `tests/design-look.test.mjs`, `tests/capture-routes.test.mjs`, `tests/components-primitives.test.mjs`, `docs/native-composition.md`_

Two sites were built out by a weaker model from a full client kit. Their pages were longer than any before them, and the builders' notes named these faults in Baseline itself.

- **The look stopped at 14 screens.** The two phone pages were 14 and 17 screens long, so the last sections of each were never looked at. `design:look` now takes up to 40 screens a width, which covers a phone page of about 30 000px. A page longer than that says in its own section of `look.md` how many pixels are outside the look and to look at the rest in the page itself.
- **A screen that had changed was called unchanged.** A second look keeps the lines of the screens that did not change. The test was the average difference over a 24 by 24 grid, and a small drawing added to a screen moved that average too little. The grid is now 48 by 48 and any one cell that moved counts. An unchanged page still reads as unchanged: 81 of 82 screens on two runs over two built sites. A `look.json` from an older look is read as "changed" once, then replaced.
- **`--base http://127.0.0.1:<port>` was refused while the site was up.** A dev server started on `localhost` listens on `::1` on some machines, and `127.0.0.1` then refuses the connection. `capture:routes`, `design:look`, `audit:composition`, `check:quality`, `audit:ui` and `record:motion` now try the other local names when a local origin does not answer, use the one that does and say so. When none answers they say what to start, before the list of skipped routes.
- **Disclosure could not be restyled from a site's stylesheet.** Its scoped rules carried the component's attribute, so `.disclosure { … }` in the same layer lost to them and the builder wrote its own `<details>` instead. The default look now has no specificity: `.disclosure`, `.disclosure > summary` and `.disclosure__body` rules in `@layer components` win wherever the stylesheet loads. The component looks the same until a site restyles it.

Two things in the builders' notes were not faults. A lone `/` route under Git Bash was already put back by every route-taking command except `design:look`, which was fixed in the previous release; `npm` still prints the rewritten path in its echo of the command, and the tools read it correctly. And `audit:composition` counts SVG and canvas drawings as "drawn objects" by design: a framed block of text is counted under surfaces, not drawings.

##### For sites

Copy the six scripts, the three tests, `src/components/Disclosure.astro` and `docs/native-composition.md`. A site that restyled Disclosure with a selector of two or more classes keeps its look; a site that relied on the component's own border or padding winning over a one-class rule of its own will now see its own rule apply.

#### A look pass: every screen, one line each, and a score

_EmDash and static · skills, tooling, docs · Copy the named files into the site · files: `scripts/design-look.mjs`, `tests/design-look.test.mjs`, `scripts/audit-composition.mjs`, `tests/audit-composition.test.mjs`, `package.json`_

The agents that built thirteen scored trial sites opened their own screenshots fifteen to thirty-eight times a run. The logs show where they looked: nearly always the wide page, and on the phone the first screen or one full-page picture (390px by about 7000px, shown so small that nothing in it can be read). Seven runs opened one phone screen below the first between them. None wrote down what it saw. The faults that cost these sites their craft score were further down the phone page.

- **`npm run design:look`** (new) cuts each page at 390px and 1440px into the screens a visitor scrolls through, sets them side by side at full size on sheets in `audit/look/`, and writes `audit/look/look.md` with one line per screen to fill: what is read first, and what is wrong (cut off, over something else, against an edge, too small, lost in a picture, out of line, an empty stretch, a placeholder). A second run keeps the lines of the screens that did not change. Two more sections hold what was fixed and the pages' score. `--check` passes when every screen has its line, every fault its answer and the six scores are written, on screens taken after the last change under `src/`.
- **A scorecard** (`site-art-direction/references/scorecard.md`, new): six questions scored 0 to 3 from the screens (the look from the client's own thing, a feature that answers the visitor's question, the job on a phone, craft, the made things, one idea carried through), with what usually holds each one at 2. The agent names its lowest question and improves the page for it.
- **The first screen and the working feature are built first and finished**, at 390px and then at 1440px, before any other section. Trial sites spread their effort evenly over six to eight sections.
- **`text-against-edge`** (new, in `audit:composition`): a line that begins or ends at the side of the ground it stands on or of the screen, confirmed in a picture of the page taken with its text unpainted. Eight scored sites give twenty places, each one seen by eye before.
- **`text-covered`** (new): a line partly or wholly behind something laid over it, read from two pictures of the page (text painted and unpainted) and confirmed by what lies on top at that point. Of four trial sites built with the legibility checks, two shipped a caption running under the photograph laid over its neighbour on the phone, and one a row of facts wholly behind a panel at 1440px; twelve public professional home pages give none.
- **`placeholder-text`** (new): "à confirmer", a "bientôt" tag on its own, digits followed by a row of dashes. Guidance: leave the element out and list the missing fact; build the page's main action with the example the brief gives.

The three findings are floor findings for a direction whose record has a `Sources` line and advisories otherwise.

#### `media:prepare` says the form that works when it is written wrongly

#### A motion tier in the record; the impression tier requires scripted motion

Seven design sprints on three briefs, from a plumber to a club whose client asked for a site that strikes, all came out with the same motion: entrances on scroll, a ticker and a slow loop. Measured, the club's pages ran 14 to 29 animations with 15 to 34 KB of script; studio-built sites of the level Baseline aims at run about 140 with several hundred. Baseline's rules kept interaction without JavaScript for every site, and the brief's permission to do more was never used.

- The Art Direction Record gains **Motion Tier**: `task`, `editorial` or `impression`, written with the client's words that decide it. `site-art-direction` ("Record the motion tier") says which facts choose each tier. `check:art-direction -- --require-references` requires the line for a new direction; an older record without it stays valid, and a line that is present is always checked.

#### A site's world comes from sources, not from a list of devices

_EmDash and static · skills, tooling, docs · Copy the named files into the site · files: `scripts/design-world.mjs`, `tests/design-world.test.mjs`, `scripts/check-art-direction.mjs`, `scripts/design-icons.mjs`, `scripts/design-system.mjs`, `scripts/audit-composition.mjs`, `tests/world-record.test.mjs`_

Twenty-one trial sites for unrelated trades (a plumber, a restaurant, a night club, a sculptor, a village association) shared one look: a paper ground, a condensed display face, labels in a mono face, a stamp set at an angle and a running band of words. The cause was Baseline's own guidance. World building listed ready devices, two lanes named a paper seed palette and condensed faces, and every example in a template or a check message was a stamp. A later reference named one example of a pinned scene, and all three sites built from it afterwards made that scene.

- **World building lists no devices.** The recipes section, the illustration column and every example of a device are gone. Step 1 is now gathering: look at each of the client's photographs, read their colours, find and save pictures of the trade's real things, write what each shows, and take the inventory, the materials, the source object and the palette from those notes. The kit's eight parts each say where their answer comes from. What remains under "Techniques" is build rules that hold for any world.
- **`npm run design:world`** (new). `search "<thing>"` lists pictures on Wikimedia Commons with their licence; `get <numbers>` saves the chosen ones into `audit/world/` and records the source, the author and whether each may be shown on the site; `palette <folder>` prints the large colours and the small vivid colours of the client's photographs as hex and oklch.
- **The display face is chosen from a specimen sheet.** Every trial site named a face from memory and justified it afterwards. `npm run design:world -- faces <kind of lettering> --text "<line>"` shows eight open faces of that kind with the site's own display line, from a pool of about 270 sorted by how the letters are built, a different sample for every site; the faces the trials kept choosing are left out unless asked for. `check:art-direction -- --require-references` checks that the record's display face is on a sheet.
- **The record names its sources.** The World block has a `Sources` line: at least two of the client's photographs and at least two pictures saved under `audit/world/`, each as a file in backticks with what the site builds from it. `check:art-direction -- --require-references` asks for the line and checks that every file exists. An older record without the line stays valid.
- **The three lanes for organisations, places and makers no longer describe a look.** They seed from `neutral` and take every colour from the photographs; the named typefaces and grounds are gone. A lane says what the visitor comes for and how the page is composed.
- **Concepts start from different sources.** Each of the two or three concepts starts from a different source object, shown in a different picture, on a different material.
- **The impression reference gives no example of a scene.** It gives three steps for finding the scene in the client's own material, and a rule for steps that replace one another: one step shows at a time (two trial sites shipped scenes in which the words of two steps showed through each other).
- **Reference research** lists sources that were read with a plain fetch and whose licence was read in November 2026, says which need a browser, and says that references set the level and never give the site its material. The technique sources are plain CSS, so nothing is rewritten from React.

A new direction, or a redesign that runs `check:art-direction -- --require-references`, gathers its sources first, writes the `Sources` line and chooses its display face from a specimen sheet.

#### `npm run verify` stays green in a site with its own typeface, and a dark ground has a way through the token tool

_EmDash and static · skills, tooling · Copy the named files into the site · files: `scripts/design-system.mjs`, `scripts/check-art-direction.mjs`, `tests/spacing-tokens.test.mjs`, `tests/world-record.test.mjs`_

Two sites were started from the current standards by a strong model, and both reported the same faults in Baseline itself.

- **`npm run verify` was red in a site with its own typeface.** Two of the starter's spacing-token tests hand the site's stylesheet to the token tool in a temporary folder. A site that loads a typeface from a package has no `package.json` there, so the tool refused the stylesheet for a face it could not find, and the tests failed for a reason that had nothing to do with them. The tests now put the font roles back to system stacks first. A site that sees `verify` red before its first edit learns to ignore it.
- **"No third voice: …" was read as a typeface.** The art-direction check took the words after that colon as the family of a third voice and asked for a specimen sheet. A role that is denied is no longer read, and the reading face used again for labels is not a third voice.
- **A dark canvas was turned into a pale page.** `design:tokens --seed-canvas <dark colour>` kept the page near white and said nothing. It now refuses, with the command that sets a dark ground.
- **The surface values can be set through the tool.** `--set "--root:--surface-light-link=<colour>"` (and the other `--surface-light-*` and `--surface-dark-*` values) is added to `:root` when the site has not set it yet, instead of being refused as an unknown name. A dark theme and the values of its light sections can so be saved in one command.
- **A failing contrast pair says where its colours come from.** A pair on a light or dark section names the `--surface-*` values it reads and their fallbacks; a failing link says that it takes the action colour and where `--color-link` is declared. On a dark theme the first failure is nearly always the light section's link on the starter's white, which the old message did not explain.
- `token-handoff.md` has a short section, "A site whose ground is dark".

Copy the two scripts, the two tests and the `site-art-direction` skill.
