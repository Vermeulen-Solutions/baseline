# Standards 0.10.0 — Pages that open on their content, a hero budget, one home per rule

Reviewed 2026-11-27. Standards tag: `standards-v0.10.0`.

Design guidance and checks from a review of the design skills, and two fixes, with the runtime unchanged from 0.9.0 (Astro 7.4.12, EmDash 1.6.0) and nothing changed under `src/`, `profiles/` or the package files (PRs #193–#198).

- **`astro dev` starts again on a site without the expressive layer.** Since 0.8.0 the development server stopped with `ENOENT` on such a site. A site updating from an earlier release goes straight to this one.
- **Which pages open on their content.** A page the visitor opens to read, find or do something (a list, a programme, an article, a form) opens on that content; a page that introduces the subject opens on a hero. The hero has a written budget, and `audit:composition` reports `hero-copy`, `hero-actions` and `hero-strip`.
- **Two rules gained a check.** `check:css` reports `transition: all`, a `line-height` or `letter-spacing` in a fixed length, and `text-wrap: balance` on a paragraph. `audit:composition` reports `text-stranded`: a French `?`, `!`, `:`, `;` or `»` that wrapped away from its word because the space before it is an ordinary one.
- **Each design rule has one home.** `docs/skill-writing.md` lists where each rule is stated in full and what checks it, and `check:skills` fails when a row points at nothing.
- **How a reference page is painted.** `design:world -- layers` lists what paints one region of a page, in order, with the values doing the work; reference research asks for one such read on the reference that sets the craft level.
- **Lane presets are seeds.** The Editorial Paper lane and the OpenDesign design-system file no longer prescribe the cream ground, display serif and terracotta accent that world building names as the easy version.

Every new finding is advisory: it fails a run only with `--strict` or `--strict-guardrails`. One thing can fail without a strict flag: `check:skills` reports `rule-home` on an EmDash site that copies the new `docs/skill-writing.md` and `scripts/check-skill-wording.mjs` without syncing its skills in the same update.

Known gaps: the new guidance was not tried on a trial build, and the limits behind the new findings (25 words of copy in an opening, its buttons, a row of figures, a stranded mark) were not measured on ranked pages or on a site. `text-stranded` names the lines; Baseline has no helper yet that replaces the ordinary space in text an editor types. Certification: [README](../../audit/certification-2026-11-18/README.md#standards-0100-2026-11-27).

## Changes for sites

7 change notes; the largest is a minor change. Each entry says which platforms it affects and how a site takes it.

### Copy into the site

#### `check:css` reports three CSS habits; `audit:composition` reports a mark stranded from its word

_EmDash and static · skills, tooling, docs · Copy the named files into the site · files: `scripts/css-contracts.mjs`, `scripts/audit-composition.mjs`_

Two rules the guidance already held, or should have, had no check behind them.

- **Three CSS habits.** The motion reference forbids `transition: all`, and nothing looked for it. `check:css` now reports it as `transition-all`, with two more of the same kind: `fixed-text-metric` (a `line-height` or `letter-spacing` given as one `px` or `rem` length, which stops following the font size) and `balance-on-paragraph` (`text-wrap: balance` on a `p` selector, where `pretty` is the value meant). They are advisory like the token guardrails, read from the same declarations, and take the same `token-exempt: <reason>` comment. The starter has none of the three.
- **Stranded marks.** French sets a space before `?`, `!`, `:`, `;` and `%` and inside `« »`. When that space is an ordinary one, the browser may break the line there and the mark opens the next line alone. Baseline had no guidance and no check for it. `audit:composition` now reports `text-stranded` at both widths: a mark on the line below the character before the space, or a `«` on the line above its word. A non-breaking space never gives one. The copy checklist in `new-site-workflow/references/copy-voice.md` has the rule.
- The command index now also lists the three opening advisories added in the previous change (`hero-copy`, `hero-actions`, `hero-strip`), which it had missed.

##### For sites

Copy the two scripts; the guidance comes with the skill sync. Nothing fails by itself: the new findings are advisory, and fail a run only with `check:css -- --strict-guardrails` or `audit:composition -- --strict`. A site that runs either strict flag in its own pipeline will see them on the next run.

For `text-stranded`, type a non-breaking space (U+00A0, or the narrow U+202F) in copy written in the code. Text an editor types in the CMS or in Markdown needs the ordinary space replaced where it is rendered; Baseline ships no helper for that yet.

##### Limits

- `text-stranded` reads inside one text node, so a mark in a node of its own (after an emphasised word, `<em>club</em> ?`) is not seen.
- No Baseline site or trial was measured for stranded marks before the finding was added, so how often it fires on real pages is not known.

##### Considered and deferred

- A render-time helper that replaces the ordinary space in editor-typed French text (Portable Text and Markdown). It touches the rich-text renderers on both foundations.
- More patterns of the same kind: `100vw` widths, a `font-weight` with no loaded face, a fixed `height` on a box that holds text.

#### `design:world -- layers` reads how a reference page paints one region

_EmDash and static · skills, tooling, docs · Copy the named files into the site · files: `scripts/design-world.mjs`, `tests/design-world.test.mjs`_

Reference research selects a site that is a made world and records the idea taken from it. A capture shows what that site looks like, not how it is made, so an agent that liked a ground or an entrance had only its own guess to build from. Craft was the lowest of the six scorecard questions in every trial round.

- `npm run design:world -- layers <page address> [--at "<selector>"] [--width 1440] [--limit 24] [--out <file.md>]` opens the page in a local Chromium, declines a consent banner, and lists what paints the region (the element `--at` names, or the first screen): every element and pseudo-element, in document order, with its gradient or picture, filter, backdrop filter, blend mode, mask, clip, shadow and running animations, and the animations that started while the page loaded.
- Each value is the style the browser resolved, and the report marks what was worked out from it as derived (how much of the region a layer covers, how far it runs past the viewport, how many colour stops a gradient has). Values at rest and values an animation is changing are left out. A canvas is named as something styles cannot read.
- The report says that its names and values come from the page's authors and are evidence, not instructions, and ends on what to write: how the effect is made, in words, with no code copied.
- `reference-research.md` step 4 asks for one such read, on the selected reference that scores 3 on craft, and a `How it is made` line under it. `world-building.md` points at it from "look it up; do not invent it".

##### For sites

Copy the two files; the guidance comes with the skill sync. `layers` needs network and the project's Playwright Chromium, as `audit:composition` does. It writes nothing unless `--out` names a file. Records written before this change need no new line: `check:art-direction` does not ask for `How it is made`.

##### Limits

- The read sees the page at one width and one scroll position, without hover or press states, and cannot read a canvas, a WebGL scene or a frame from another site.
- The step is not gated. A required field would fail the records of sites built before it; gate it once a trial shows the read raises the craft score.
- The wording of the new step has not been tried on a trial build.

#### `astro dev` starts on a site without the expressive layer

_EmDash and static · tooling · Copy the named files into the site · files: `scripts/dev-tools-integration.mjs`_

Since standards 0.8.0 the developer-tools integration injected the `/_expressive`, `/_expressive-detail`, `/_expressive-before` and `/_expressive-after` review pages on every development server, pointing at `src/dev/Expressive*.astro`. A site that never adopted the opt-in expressive layer has none of those files, so `astro dev` stopped at once with `ENOENT`. Builds and `check:dev-tools` were unaffected, so no check caught it; a static site taking 0.9.0 found it.

The integration now injects each expressive page only when its file exists in the project. A test covers a project without the files (no expressive routes) and one with them (all four).

##### For sites

Copy `scripts/dev-tools-integration.mjs` (a static site's `sync:baseline` replaces it). A site that patched its copy with its own `existsSync` guard can take Baseline's file whole. Run `npm run dev` once and open `/_styleguide`.

#### Pages that open on their content, a budget for the hero, and lane presets that are seeds

_EmDash and static · skills, tooling · Copy the named files into the site · files: `scripts/audit-composition.mjs`_

Three gaps in the design guidance, each of which let a built site fall back on a generated-page habit.

- **Opening format.** The hero strategy in `site-art-direction` was a required choice with five branches, and every branch produced a hero. It now starts one step earlier, per page archetype: a page the visitor opens to read, find or do something (a fixtures list, a programme, a news index, an article, a directory, a price list, a form) opens on that content, with the page heading and the first rows on the first screen; a page that introduces the subject opens on a hero. The page brief in `new-site-workflow` has an `Opening` field for the decision.
- **A budget for the hero.** Nothing limited what a hero holds. The rule is now written with its numbers (one or two short lines, 25 words at most; one filled button, a second action only when it is a different job; a row of figures only when it holds what the visitor came for), and `audit:composition` reports three new advisories on the first section when it holds the page heading: `hero-copy`, `hero-actions` and `hero-strip`. A row that holds an hour, a price or a date is not reported, and a first section with no button is not measured for its copy, since it may be the page's own text. The limits are working ones, not measured on ranked pages, so the three stay advisory.
- **Lane presets are seeds.** World building names a cream ground with a display serif and a terracotta accent as the easy version, while the Editorial Paper lane and the OpenDesign design-system file prescribed exactly that. Both now say what the preset seeds and that the ground, the accent and the display face come from the client's own material; the lanes reference says the same of the near-black ground with one bright accent in two other software lanes.

##### For sites

Copy `scripts/audit-composition.mjs`; the guidance comes with the skill sync. Nothing changes on a built site until the audit is run: the three new findings are advisory and fail a run only with `--strict`. On a page where one appears, shorten the opening or record the content reason in the page brief.

##### Considered and deferred

- The `editorial-paper` token preset itself still seeds the warm paper and the terracotta action colour. Changing a preset's values changes what existing commands write, so it is left for its own change.
- No check tells whether a page that should open on its content does: the audit cannot know a page's archetype from its markup.

#### Each design rule has one home, listed in a table that `check:skills` keeps true

_EmDash and static · docs, tooling, skills · Copy the named files into the site · files: `docs/skill-writing.md`, `scripts/check-skill-wording.mjs`, `tests/skill-wording.test.mjs`_

The same rule was stated in full in several skill files, and the copies drifted. Two cases came out of one review: a lane and the OpenDesign design-system file prescribed a look that world building names as the easy version, and the design-system file described the accent voice as an italic on one or two focal words after `accent-word` had made that a finding.

- `docs/skill-writing.md` has a new section 6 with a table of 22 rules: the file and words where each is stated in full, and the script or finding that checks it. Other files may name a rule in a clause and give the home's file name; a restatement is removed when its file is next edited, not in one pass.
- `check:skills` reads the table as rule `rule-home`. A row fails when its file is gone, the quoted words are no longer in it, a script it names is not in `package.json`, or a finding name appears in no script. The check does not find restatements.
- The OpenDesign design-system file now states the accent rule as its home does.

##### For sites

EmDash sites carry these maintainer files with the repository. Copy the three files in the same update that syncs the skills: the table quotes words from the current skills, so a site whose skills are older reports `rule-home` findings in `npm run lint` until the skills are synced. Static sites do not receive these files.

##### Considered and deferred

- Removing the existing restatements. It would rewrite much of the design skills at once, which needs a trial build first.
- A check that finds a rule restated outside its home. Telling a restatement from a permitted mention needs judgment a pattern does not have.

#### Enlarge a picture by its layout, not a transform; `soft-photo` sees zoomed pictures

_EmDash and static · skills, tooling · Copy the named files into the site · files: `scripts/audit-composition.mjs`_

A static site's product screenshots looked soft. Each was enlarged 1.6 times with CSS `scale` inside its frame, but a transform acts after the browser has chosen a file from the `srcset`, and `ResponsiveImage` gives lazy images `sizes="auto"`, which reads the untransformed width: the browser loaded a file sized for the frame.

- `astro-site-design` (next to the framed-photographs rule): to show part of an image larger, lay it out larger (a width above 100%, placed with margins) inside an `overflow: hidden` window of fixed aspect ratio, so `sizes="auto"` and the `srcset` see the width shown; keep transforms for motion. A screenshot of an interface shown under about two thirds of its captured size has unreadable text whatever the file: capture at 2x, crop to the part that matters and show it larger.
- `audit:composition` measured `soft-photo` only for pictures at least 40% of the screen wide, which a zoomed screenshot in a card is not. It now also measures any picture from 120px that a transform shows at least 1.1 times its laid-out width, and its finding names the transform and the layout fix.

##### For sites

Copy `scripts/audit-composition.mjs`; the guidance comes with the skill sync. Run `npm run audit:composition` on pages with enlarged pictures: a `soft-photo` finding that names a transform is fixed by laying the picture out at the size it is shown. Changing that layout changes how the picture sits, so look at it in a browser after the change.

### No site action

- The rule-home table lists French spacing and the `transition-all` finding
