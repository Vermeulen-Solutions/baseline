# Standards 0.7.0 — Drawings and built pages

Reviewed 2026-11-20. Standards tag: `standards-v0.7.0`.

What the woodcarver sprint that tested 0.6.0's drawing rule found, and two loose ends from the design sprints.

- **Drawn figures get the world's medium and a size.** A figure from an open set that is only recoloured reads as clip-art; treated in the site's own medium and shown at least 480px wide it reads as made. `design:icons` lists figurative sets first.
- **A record still on its lane's defaults fails the art-direction gate** (minor: a site with such a record turns red until it records its own decisions).
- **Built pages are `built: <route>` rows** in the concepts table; the bar reads the home page as it stands.
- **The record heading appears only as the heading** in AGENTS.md, so a script cannot paste a record into a sentence.
- **Visual references are checked against their manifest in CI**, and the release's Certify step runs the visual suite.

Runtime and development dependencies and the database schema are unchanged from 0.6.0.

Certified source: commit `dcf4a99744685eecb98ca74c4e55750452aa1a3c`. Evidence: [verification-0.7.0.json](../../audit/certification-2026-11-18/verification-0.7.0.json) and the certification README.

### Review and merge by hand

#### The record heading appears only as the heading in AGENTS.md

_EmDash and static · docs · Review and merge by hand; a decision per site_

AGENTS.md's gate paragraph named the record as `## Art Direction Record` in the middle of a sentence. A trial's script that searched for that text found the sentence before the real heading and pasted the record into it; `check:art-direction` caught it afterwards. The paragraph (EmDash and static profiles) now says "Art Direction Record section", so the heading text appears only where the heading is.

##### For sites

Optional: in your AGENTS.md, reword the gate paragraph the same way. Nothing else changes.

### Copy into the site

#### Built pages are "built" rows in the concepts table

_EmDash and static · tooling, skills · Copy the named files into the site · files: `scripts/check-art-direction.mjs`, `tests/reference-research.test.mjs`, `.agents/skills/site-art-direction/references/reference-research.md`, `.agents/skills/site-art-direction/SKILL.md`_

The concepts table allowed one "chosen" row, and the guidance told an agent to move that verdict to each new score of the built page and mark the earlier rows "not chosen: superseded". A trial with two built pages scored over three rounds ended with five rows of the chosen direction marked "not chosen".

- A Stage 5 score of a built page of the chosen direction is a row with the verdict `built: <route> <note>` (`built: / round 1`, `built: /works final`). The concept keeps its `chosen` verdict; exactly one concept is still chosen, and built rows do not count towards the two concepts to score.
- `check:art-direction` judges the bar on the home page's last `built` row, or on the chosen concept before the home page is built. Other pages' last rows are printed as advice (`Advisory: the built page /works scores …`), never failed. A `built` row without a route fails.
- The art-direction skill says to replace the record by its exact heading line or with `design:tokens --write-record`.

##### For sites

Copy the script and its test with the skill sync. Existing tables stay valid: rows marked `not chosen: superseded` still pass.

#### Drawn figures get the world's medium and a size; lane-default records no longer pass the gate

_EmDash and static · skills, tooling · Copy the named files into the site · files: `scripts/design-icons.mjs`, `scripts/design-system.mjs`, `scripts/check-art-direction.mjs`, `scripts/audit-composition.mjs`, `tests/design-icons.test.mjs`, `tests/art-direction.test.mjs`, `tests/audit-composition.test.mjs`_

A design trial tested the drawing rule (figures come from an open-licence set through `design:icons`). The rule fixed the crude hand-drawn figures. But a set figure that was only recoloured still read as "a logo or clip-art". The same owl read as stencil paint once three things were done: a spray filter and stencil bridges were applied, it was shown at about 780px, and it sat on the log it was sprayed on. At 150 to 300px a figure with the same treatment was still judged an icon.

- Site art direction: the Drawings rule in world building now asks for three things. Each figure gets the world's medium as a filter and a mask. It is shown at least 480px on its short side. It is set on the object it marks. The rule also notes that below about 300px a figure stays an icon. A new reference, `drawing-treatments.md`, has the recipes: the spray filter and stencil bridges from the trial, an ink stamp, and a brand burnt into wood. It also covers breaking the set's symmetry, the cost of filters in motion, and the reviewer's question.
- `design:icons search` lists figurative sets first, using Iconify's set category. It marks UI and emoji sets ("read as an interface", "read as a chat") and searches 200 icons by default. For "owl", game-icons now comes first; it used to be at row 24 after about twenty UI sets. `get` ends with the treatment reminder.
- `design:tokens --init-client` (and `--write-record`) mark the record they write as the lane's defaults with a comment under the heading. Every `check:art-direction --require-*` run fails until the record is the site's own and the comment is deleted. A trial's gate passed on the generic lane record before any direction existed.
- `audit:composition` `repeated-run` compares neighbouring tall items by how they are laid out: the picture's share of the width, picture beside or above the text, the number of pictures, and the ground. It no longer compares them by tag and class. A register in five arrangements on three grounds is no longer reported. Identical or only mirrored blocks still are.

##### For sites

Copy the files. The skill text arrives with the site's skill sync. A site whose `AGENTS.md` record still has the lane-defaults comment fails `--require-*` checks: write the site's own record, then delete the comment.
