# Standards 0.6.0 — Design sprints

Reviewed 2026-11-20. Standards tag: `standards-v0.6.0`.

What eight design sprints on four client briefs, and one redesign of a launched site, changed in how Baseline designs a site. Each sprint was audited and followed by fixes before the next (PRs #130–#154).

- **Motion that runs.** The production minifier broke every scroll-driven animation on built sites; the starter now writes them as longhands and `check:css` catches the pattern. Every site that uses `data-reveal` or `data-scroll` should take this release.
- **A first screen that opens settled.** `check:quality` reports a scroll-driven entrance caught part-way on the first screen (`first-viewport-scroll-motion`), and `capture:routes --motion` shows the first screen as it paints.
- **References and a comparison pass that set the level.** Reference research starts from studio work and requires one made world; each page is compared with its references on one sheet, and the concept bar is enforced at Stage 5 with a way to end.
- **World building.** A governing idea, a world record (source object, inventory, surfaces, motions by `@keyframes` name), signature moments that pass four tests (now including the page's main visitor), and `audit:composition` floor findings for bare pages, stretched photographs and recorded motions that never run.
- **Drawings from open sets.** `design:icons` finds figures in open-licence sets with credits; code keeps geometry only.
- **The expressive layer and smooth scroll**, opt-in, for image-led sites.
- **Redesigning a launched site.** Guidance for raising a direction in place, a superseded record, and a recipe for rehearsing a redesign on a copy and taking it live.
- **Tools:** `serve:static`, captures clipped to the viewport with overflow flagged, a per-route timeout, and the slow scroll for studio pages.

Runtime and development dependencies and the database schema are unchanged from 0.5.1.

Certified source: commit `22948b4ce371e7caff923ea2eeca954cbaa2bdc8`. Evidence: [verification-0.6.0.json](../../audit/certification-2026-11-18/verification-0.6.0.json) and the certification README. The clean clones ran on `bfd469c`, which differs from the certified commit only in the local visual reference images renewed during certification (#154).

### Changes how pages look: decide per site

#### Scroll-driven motion runs on the built site

_EmDash and static · styles, tooling, skills · Copy the named files into the site · files: `src/styles/global.css`, `src/styles/expressive.css`, `scripts/css-contracts.mjs`, `tests/css-contracts.test.mjs`, `scripts/audit-composition.mjs`_

The production CSS minifier folds `animation: x linear both` and `animation-timeline: view()` of one rule into `animation: linear both x view()`. Browsers reject that value (the timeline is reset-only in the shorthand), the animation name computes to `none`, and the motion never runs on the built site, while the unminified dev server shows it. The starter's shared scroll reveal (`data-reveal`) and the expressive scroll effects (`data-reveal="frame"`, `"mask"`, `data-scroll="open"`, `"recede"`, `"rise"`) were written that way, so on every production build they have not run; a trial found it when its own scroll entrances stopped.

- The starter's scroll-driven rules are written as longhands (`animation-name`, `animation-timing-function`, `animation-fill-mode`), which survive minification.
- `check:css` fails on a rule that sets the `animation` shorthand and `animation-timeline` together.
- The world-building and fluid-tokens recipes show the longhand form.
- `audit:composition` counts objects turned with the independent `rotate` property as depth, as well as `transform: rotate()`.
- The Stage 5 comparison may give one reviewer every page's sheets at once.

##### For sites

Copy the files. Pages that use `data-reveal` or the expressive scroll attributes start animating on the built site: check them once on the preview. Run `npm run check:css` and rewrite any rule it names in the site's own CSS as longhands.

#### The starter makes room for built objects and wide photographs

_EmDash and static · styles, components, docs · Copy the named files into the site · files: `src/styles/global.css`, `src/lib/responsive-image.ts`, `tests/presentation-boundaries.test.mjs`_

A design trial built its pages as objects from the site's world and found the starter in the way:

- Every list item was held to the reading measure (68ch, about 630px), so a works register, a woodpile or a wall of plates built as a list shrank to a third of its grid, and only a browser inspection found why. Classed list items, the parts of built objects, now take their grid's width; prose list items keep the measure.
- `ResponsiveImage` offered candidates up to 1400px, so a photograph shown at full width on a large or dense screen was stretched and `audit:composition` reported it as `soft-photo`. Candidates now go up to 2800px, never past the file's own width.
- The interaction rule in `AGENTS.md` allowed only opacity, transform, translate and scale, while the world-building recipes draw paths with `stroke-dashoffset` and reveal paint with `clip-path`. It now allows `rotate`, and on the world's drawn objects those two reveals.

##### For sites

Copy the files. List items with a class lose the reading-measure cap: check list-built objects once on the preview. Builds produce larger image candidates for wide originals.

#### The composition audit reports a bare page

_EmDash and static · tooling, docs · Copy the named files into the site · files: `scripts/audit-composition.mjs`, `tests/audit-composition.test.mjs`_

`audit:composition` passed trial builds whose pages were made only of type, photographs and rules, because it looked for template layouts and not for what a made page has.

- New `bare-page` finding: the page lacks three or more of five things a made world has: a surface (a textured or patterned ground, an edge drawn on a pseudo-element), three or more drawn objects (SVG or canvas at least 32px), three type voices, depth (a rotated or masked object) and motion (an animation running while the page is scrolled, measured with motion allowed before the audit switches to reduced motion). Calibrated on studio-built sites for a race, an embroidery shop and a school (none reported; all five present on two of them, four on the third) and on three trial builds (all reported, three or four missing).
- Each route's summary line now prints the counts: elements, type voices, surfaces, drawings, rotated or masked objects and animations.

#### audit:composition reports the split hero and uniform galleries, and a signature must stand out

_EmDash and static · tooling · Copy the named files into the site · files: `scripts/audit-composition.mjs`_

A trial site that followed the art-direction method passed `audit:composition` with one finding while still opening on a heading beside a photograph and showing fifteen works in equal frames. The audit now also reports:

- `split-hero`: the page opens with its heading beside a photograph narrower than 60% of the screen;
- `uniform-gallery`: six or more pictures in equal frames in one grid, none larger than the rest;
- `no-signature` more strictly: a large heading counts as a statement only when it is markedly larger than the page's other headings (or a giant opening line at least twice their size), and a frame shape alone no longer counts.

#### Copy voice and the tells of model copy

_EmDash and static · tooling, skills, docs · Copy the named files into the site · files: `scripts/check-quality.mjs`, `scripts/copy-tells.mjs`, `tests/check-quality.test.mjs`, `tests/copy-tells.test.mjs`_

#### Reference research: the concept bar judges the design, and captures survive other people's sites

_EmDash and static · tooling, skills, docs · Copy the named files into the site · files: `scripts/check-art-direction.mjs`, `scripts/capture-routes.mjs`, `tests/reference-research.test.mjs`, `tests/capture-routes.test.mjs`_

Two trials with an owner's phone photographs stalled under the concept bar: every reviewer named the photographs as the ceiling, the chosen concept stayed one or two points under the references' median, and `check:art-direction` (run by `verify`) could then never pass on an honest site. The same research spent most of its time on captures that timed out, on cookie banners that cost good sites their score, and on a required prompt-library candidate that scores low by construction.

- The concept bar is set on the seven design lines: the chosen concept reaches the selected references' median on first screen, specificity, type, composition, craft, phone and fit together, and scores 2 or more on each. The photographs line is still scored and shown; under 2, it becomes the list of photographs to commission, and the design frames the photographs rather than stretching them.
- No candidate has to be a prompt, template or system. The first round of searches covers the same trade, a neighbouring trade and studio case studies; for a small trade the last two usually fill the selection.
- One fresh reviewer scores; a second moved scores by a point or two and doubled the cost.
- `capture:routes` waits for `load` and then up to 15 seconds for the network to settle, instead of failing on busy sites after 90 seconds; a full-page capture that takes over 45 seconds is skipped while its viewport frames are kept; a page behind a bot wall or one that does not load is reported as `SKIPPED` and the run goes on. `--decline-consent` answers a cookie banner with its reject or necessary-only button (French, English, German, Italian, Spanish, Dutch) before capturing.

##### For sites

Copy the two scripts and their tests. A references file whose concept table was under the old bar only through the photographs line now passes.

#### Expressive layer: image-led stages, ruled indexes, frame shapes, fitted lines, scroll reveals and page-transition styles

#### The first screen never opens on a scroll-driven entrance caught part-way

_EmDash and static · tooling, skills, docs · Copy the named files into the site · files: `scripts/check-quality.mjs`, `tests/check-quality.test.mjs`, `scripts/capture-routes.mjs`, `tests/capture-routes.test.mjs`, `.agents/skills/astro-site-design/references/interaction-techniques.md`_

A launched site opened every desktop visit on a half-tilted, faded board. The board's top showed at the bottom of the first screen at 1440×900, and its entrance was scroll-driven (`animation-timeline: view()`, starting tilted, shifted and at 40% opacity), so its progress at load came from where it sat. The guidance already said the first screen is never hidden, but nothing caught this case: `check:quality` only reported a first screen that starts mostly transparent, and `capture:routes` runs with reduced motion and finishes every animation, so the evidence showed a settled board.

- `check:quality` reports `first-viewport-scroll-motion`: an element on the first screen, at the phone or desktop width, whose `view()` animation changes opacity, rotation, scale, blur or clip and is part-way through straight after load. A parallax that only translates is not reported. The run exits 2 on it, like every other finding.
- `capture:routes --motion` captures with full motion and adds a `load` frame: the first screen as it paints, before any animation is forced to its end. Without `--motion`, captures stay as they were (reduced motion, every animation at its end).
- The interaction guidance says nothing on the first screen rides a scroll-driven entrance at any width: give it no entrance, or play it once when it comes into view and leave it still when it is already on screen at load.

##### For sites

Copy the two scripts and their tests. A site with a scroll-driven entrance on an element that shows on the first screen now fails `check:quality` until the entrance is removed or plays once on view.

#### Impeccable runs by its commands, with the brief where it can read it

_EmDash and static · skills, docs · Copy the named files into the site · files: `.agents/skills/new-site-workflow/references/impeccable-passes.md`, `profiles/static/project/AGENTS.md`, `profiles/static/project/README.md`_

- `audit:composition` gains two findings. `soft-photo`: a photograph at least 40% of the screen wide is shown wider than its file (read from the file itself, since a srcset hides the stretch in `naturalWidth`). `world-motion`: an animation named in the record's World › Motion line never runs on the audited routes while scrolling; the record is read from `AGENTS.md` in the working directory, or `--record <file>`.
- `bare-page`, `soft-photo` and `world-motion` are floor findings: the command exits 1 on them. The other findings stay advisory and fail only with `--strict`. On the three studio-built sites used to calibrate the bare page, the floor finds nothing.
- `--json` and `--out` now write `{ routes, site, named }` instead of the bare route list.
- The World › Motion line names each motion by its `@keyframes` name in backticks (`stamp-lands`: the stamp on the label); `check:art-direction` requires three.
- The world-building guidance sets an object in every section of every page, never shows a photograph wider than its pixels (the first screen is carried by an object or a generated artefact with the photograph inside), and builds each motion under its recorded name. Stage 6 and Express Checkpoint C run `audit:composition` on the home page and one page of each kind; the gate needs no floor finding.

##### For sites

Copy the two scripts and their tests. A site whose record names motions without backticks fails `check:art-direction` until each motion carries its `@keyframes` name. A site that runs `audit:composition` in a script now gets exit 1 on floor findings.

### Arrives with the site's sync

#### The world's motion comes in four layers; labels and lettering come from the world

_EmDash and static · skills · Arrives with the site's skill or source sync_

Measured on studio-built sites for a race and an embroidery shop, both built with Astro and plain CSS with no animation library: their home pages run 70 to 140 animations, and the page feels alive because the motion belongs to the subject (mud lands on the page, words are stamped, a route draws itself, contour lines drift with the scroll). The trial builds ran two world motions and nothing else.

- World building's motion step names four layers: one orchestrated arrival on the first screen, three to five named world motions that bring the objects in as the visitor scrolls (with the starter's quiet `data-reveal` entrance for the plain text between them), one or two ambient loops of 8 seconds or more, and feedback. Recipes show a world motion on a view timeline, a register arriving item by item, and an ambient loop paused on hover and focus.
- Labels and the utility voice come from the world's own lettering. The same sites use dozens of small capitals, mono labels, middle dots and arrows as the printing of their bibs, tickets and boards, so the guidance names what makes them work (the object's real fields) rather than banning them.
- The interaction motion reference keeps its restraint for controls and for text being read, and points to world building for the site's motion. The Impeccable passes keep the four layers: `animate` and `quieter` tune their timing rather than removing them.
