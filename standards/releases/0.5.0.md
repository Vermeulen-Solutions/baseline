### Changes how pages look: decide per site

#### Analytics with consent, and embeds that load on click

_EmDash and static · components, docs, skills · Copy the named files into the site · files: `src/lib/consent.ts`, `src/lib/load-on-click.ts`, `src/components/Analytics.astro`, `src/components/ConsentBanner.astro`, `src/components/VideoEmbed.astro`, `src/components/MapEmbed.astro`, `src/layouts/Base.astro`, `src/env.d.ts`_

Both Base layouts now render `Analytics.astro` and `ConsentBanner.astro`. They produce nothing until a measurement id is set in the build environment, and tags load only on `PUBLIC_ANALYTICS_HOSTS`, never on previews or locally.

- **`PUBLIC_CF_BEACON_TOKEN`:** Cloudflare Web Analytics, cookie-free, no banner.
- **`PUBLIC_GA_ID` / `PUBLIC_GTM_ID`:** Google Consent Mode v2 with every type denied until the visitor agrees.
  - `PUBLIC_CONSENT_MODE=strict` loads nothing before consent.
  - Choices are remembered per `PUBLIC_CONSENT_VERSION`.
  - `data-track` attributes send click events.
- **The banner** offers Accept all, Reject all and a per-category choice. It never takes focus on load, reopens from any `data-consent-open` element, and takes all its labels as props.
- **`VideoEmbed.astro` and `MapEmbed.astro`:** YouTube through youtube-nocookie.com, Vimeo with `dnt=1`, maps by embed URL. They contact the provider only on click, with a real link without JavaScript.

##### For sites

1. Copy the files listed above and add `<Analytics slot="body-end" />` and `<ConsentBanner slot="body-end" />` to the Base layout, with labels in the site's language.
2. Set the ids and `PUBLIC_ANALYTICS_HOSTS` in the production build environment, and add a "Cookie settings" link with `data-consent-open` to the footer.
3. With a CSP, add the origins from `.env.example` to `CSP_SOURCES`.
4. Name the providers in the privacy notice.

#### Inline field errors in enhanced forms

_EmDash and static · components, docs · Copy the named files into the site · files: `src/components/Form.astro`_

An enhanced `Form.astro` shows a message under a field once the visitor has touched it and left it invalid (`:user-invalid`, with a blur fallback), never on load.

- **Message text:** written in the page's language through `data-error-required`, `data-error-type` and the other `data-error-*` attributes, falling back to the browser's own message.
- **Screen readers:** the message joins the field's `aria-describedby` (an existing hint stays) and sets `aria-invalid`.
- **Clearing:** both are removed as soon as the value is valid. Server errors from `FormError` are untouched.

##### For sites

Copy `src/components/Form.astro`, then add `data-error-*` messages in the site's languages to the fields of each form.

### Copy into the site

#### Accessibility scan and share-image check in check:quality

_EmDash and static · tooling, dependencies, skills · Copy the named files into the site · files: `scripts/check-quality.mjs`, `tests/check-quality.test.mjs`_

`npm run check:quality` gains two checks:

- **`axe`:** an axe scan for WCAG 2.x A/AA (2.2 included), reporting violations of serious or critical impact. It uses the new pinned development dependency `@axe-core/playwright` 4.14.0; `--no-axe` skips the scan.
- **`share-image`:** an indexable page whose `og:image` is missing, fails to load, is not an image, or is over 600 KB (link previews drop larger ones).

On Baseline's own pages axe finds nothing serious. The demo has no default share image.

##### For sites

Copy `scripts/check-quality.mjs` and `tests/check-quality.test.mjs`, and install the dependency with `npm install -D --save-exact @axe-core/playwright@4.14.0`. On EmDash sites, set a default share image in the SEO settings.

#### Launch readiness in check:quality, and placeholders instead of inventions

_EmDash and static · tooling, skills, docs · Copy the named files into the site · files: `scripts/check-quality.mjs`, `tests/check-quality.test.mjs`, `PRODUCT.example.md`_

`npm run check:quality` reports what an unattended build leaves behind:

- `placeholder`: a `[[placeholder: …]]` marker, or an empty slot marked `data-placeholder`;
- `default-identity`: the starter's title, site name or tagline, or an example.com, `.test` or `.invalid` address;
- `multiple-h1`;
- `inline-handler`: `onclick=` and friends, which a CSP blocks;
- `javascript-url`;
- `form-no-destination`: a form with `action="#"`.

The content-patterns reference makes the marker the rule when a fact is missing. `PRODUCT.example.md` gains Facts (only what the owner said), Placeholders, Assumptions and page status.

##### For sites

Copy `scripts/check-quality.mjs` and `tests/check-quality.test.mjs`, run the check, and replace any starter identity and placeholders it lists. Add the new sections to the site's `PRODUCT.md` when useful.

#### Opening hours, on the page and in structured data from one list

_EmDash and static · components, docs · Copy the named files into the site · files: `src/lib/opening-hours.ts`, `src/components/Hours.astro`, `src/lib/structured-data.ts`_

`src/lib/opening-hours.ts` validates a list of opening hours (days, and times on the 24-hour clock). Invalid entries are dropped, never guessed. The list feeds two places:

- **The Organization graph:** as `openingHoursSpecification`, from the baseline-metadata plugin's `options.organization.openingHours` on EmDash sites.
- **`Hours.astro`:** as a table with one row per weekday, day names and times in the page locale, closed days labelled and split days listed.

##### For sites

Copy `src/lib/opening-hours.ts` and `src/components/Hours.astro` (and the updated `src/lib/structured-data.ts` on EmDash sites). Keep the hours in one module and pass that list to both the metadata options and `Hours`.

#### Content-Security-Policy for static sites

_static · tooling, docs · Copy the named files into the site · files: `scripts/static-csp.mjs`, `scripts/baseline-features-integration.mjs`, `src/lib/content-security-policy.ts`_

Static sites can now have the same computed policy as EmDash sites. With `CSP_MODE=report` or `enforce` set in the build environment or `.env.production`, the build:

- hashes every inline script and style across the built pages into one site-wide policy;
- adds `CSP_SOURCES`;
- writes the policy for `/*` to `dist/_headers`, which Cloudflare and Netlify read, and to `dist/.baseline-csp.txt` for other hosts.

A `public/_headers` file that already sets a policy is left alone. The policy builder is now shared: `src/lib/content-security-policy.ts` ships to static sites, and `scripts/static-csp.mjs` runs from the features integration.

##### For sites

Copy the three files, then build with `CSP_MODE=report`. Check a preview deployment for `csp-violation` findings with `npm run check:quality -- --base <preview origin>`, add any third-party origins to `CSP_SOURCES`, and switch to `enforce`.

#### Token tests pass on a site with its own lane

_EmDash and static · tooling · Copy the named files into the site · files: `tests/fluid-tokens.test.mjs`, `tests/token-contract.test.mjs`_

Two token tests compared the site's stylesheet with the starter's exact values: the default spacing scale, the starter page colour, and the text-resize sample. A site that ran `design:tokens --init-client` has the strict theme and its own lane values, so its `verify` failed. Those exact-value checks now run only on the starter stylesheet. A client stylesheet is still checked for the token names, types and the text-resize rule.

##### For sites

Copy `tests/fluid-tokens.test.mjs` and `tests/token-contract.test.mjs` if `npm test` fails on them after a lane was initialised.

#### Day-2 recipes for everyday requests

_EmDash and static · skills · Arrives with the site's skill or source sync_

`new-site-workflow/references/day-2-recipes.md` gives each everyday request on a built site its home and its proof:

- add a page;
- rebrand (tokens, fonts, icons, name, share image, business facts);
- connect a form;
- add a language, a collection or a component;
- show a video, map or opening hours;
- turn on analytics.

Each recipe ends with the checks that prove it: `check:quality`, `audit:ui` and the design gate. It is routed from the workflow's "When / Read" table.
