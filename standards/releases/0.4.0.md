### Changes how pages look: decide per site

#### Sections open with their first entry; folded content gets audited

_EmDash and static · components, tooling, skills, docs · Review and merge by hand; a decision per site · files: `scripts/audit-ui.mjs`_

**Sections open with their first entry.** In the static profile, `gatedRoutes()` in `src/lib/posts.ts` lists sections with nothing published yet (the posts index until its first post). The navigation, the sitemap and the index's `noindex, follow` all read that one rule, so no link points at an empty page. The site working rules describe the same practice for EmDash sites.

**Folded content gets audited.** `audit:ui --open-details` opens every closed `<details>` outside the header and navigation before measuring, so folded content gets checked. The rollout reference asks for one pass with it at phone widths.

##### For sites

- **Static sites:** add `gatedRoutes()` to `src/lib/posts.ts` (with a site's own sections), filter the Base layout's navigation by it, use it in `sitemap.xml.ts`, and pass `robots: 'noindex, follow'` from an empty index.
- **EmDash sites:** add menu items only for sections with content.
- **All sites:** take `scripts/audit-ui.mjs` with the next helper sync.

#### Zero-JS interaction choreography: page transitions, dialog exits, hover gating

_EmDash and static · styles, components · Review and merge by hand; a decision per site · files: `src/styles/global.css`, `src/layouts/SiteShell.astro`, `src/layouts/Base.astro`, `src/components/Card.astro`, `src/components/Heading.astro`, `src/components/PhotoGallery.astro`, `scripts/css-contracts.mjs`, `scripts/design-system.mjs`_

SiteShell takes an opt-in `pageTransitions="cross-document"` prop that turns on native cross-document view transitions (CSS only, skipped with reduced motion); the starter Base layouts use it and hold the header with `data-vt-header`. Dialogs now animate out as well as in (`allow-discrete` display/overlay, backdrop fade), the phone Menu panel settles in with `@starting-style`, every `:hover` rule in `global.css` sits behind `@media (hover: hover)` so tapped controls do not stay highlighted, and clickable Cards zoom their media by `--card-media-hover-scale` on hover and keyboard focus. The motion and radius scales gain `--ease-exit` and `--radius-pill`, focus rings read `--focus-ring-width` and `--focus-ring-offset`, and references to names no stylesheet defined (`--ease-out`, `--radius-sm`, `--radius-container`, `--ease-standard`) now use real tokens; the documented `--duration-normal` hook still overrides the card entrance and reveal timings. `check:css` reports any `var()` naming an undefined duration, ease, radius, shadow, z or focus-ring token (`undefined-token`, advisory).

##### For sites

`global.css` and Base are site-owned, so nothing moves until a site merges them; decide per site because hover, dialog and transition behaviour changes. Merge the new `@theme` tokens first (`--ease-exit`, `--radius-pill`, `--focus-ring-width`, `--focus-ring-offset`), then the hover-gated and dialog blocks. To adopt page transitions, add `pageTransitions="cross-document"` to the site's `SiteShell` (on EmDash, `getRequestContext()?.editMode ? 'none' : 'cross-document'` as the starter Base does, so the visual editor keeps plain navigation) and `data-vt-header` to its single sticky header, then check navigation in Chromium with and without reduced motion; a site that already uses `<ClientRouter />` keeps its router and does not need the prop. A site that does not want the card zoom sets `--card-media-hover-scale: 1`. Run `npm run check:css -- --guardrails` and replace any `undefined-token` names it lists.

### Review and merge by hand

#### Real 404 status, security headers, /llms.txt and a quiet unknown-block fallback

_EmDash · components, delivery · Review and merge by hand; a decision per site · files: `src/middleware.ts`, `src/lib/security-headers.ts`, `src/pages/llms.txt.ts`, `src/lib/llms-txt.ts`, `src/components/RichText.astro`, `src/components/PortableTextUnknown.astro`, `src/lib/portable-text-fallback.ts`, `"src/pages/[slug].astro"`, `"src/pages/posts/[slug].astro"`, `"src/pages/category/[slug].astro"`, `"src/pages/tag/[slug].astro"`_

A missing page, post, category or tag used to answer with a 302 redirect to `/404`, which search engines read as a soft 404; the routes now rewrite to the 404 page, so the URL stays and the status is 404. The middleware adds `X-Content-Type-Options: nosniff`, a `Referrer-Policy`, a minimal `Permissions-Policy` and, on HTML, `Content-Security-Policy: frame-ancestors 'self'`, each only when the response does not set it already. `/llms.txt` lists published pages and posts (title, canonical URL, excerpt) and skips entries marked noindex. A Portable Text block type with no renderer no longer prints a hidden warning into public HTML: it renders nothing, logs one server warning per type and shows a placeholder in development.

##### For sites

Take the four route files when they are unchanged from the starter; a site that customised them replaces each `return Astro.redirect("/404")` with `return Astro.rewrite("/404")`. Merge the middleware wrapper and copy `src/lib/security-headers.ts`; if the site or its proxy already sends a Content-Security-Policy or X-Frame-Options, nothing is added on top. Add `src/pages/llms.txt.ts` and `src/lib/llms-txt.ts` and extend its sections when the site has other public collections or routes. Copy the unknown-block fallback and register it in RichText (`unknownType`). After deploying, check a missing URL returns 404 and that `/llms.txt` lists the expected pages.

#### One brief: PRODUCT.md

_EmDash and static · skills, docs, tooling · Review and merge by hand; a decision per site_

Baseline's optional brief was `PROJECT.md`, while the `impeccable` skill reads and writes `PRODUCT.md`. Sites that used both had two briefs that drifted apart.

There is now one brief, `PRODUCT.md`. `PRODUCT.example.md` follows Impeccable's product schema and adds Baseline's decisions table and source map:

- **Ownership:** goes under Operating Context.
- **Claims:** go under Evidence on Hand.
- **Page briefs:** stay in the page notes.

`PROJECT.example.md` is retired (listed in `scripts/retired-paths.mjs`). `baseline:inspect` still reports a legacy `PROJECT.md` so it can be found and merged, and `docs/project-context.md` gives the merge, section by section. Skills, `AGENTS.md` templates and docs now name `PRODUCT.md`.

##### For sites

On a site with both `PROJECT.md` and `PRODUCT.md`:

1. Merge `PROJECT.md` into `PRODUCT.md` following "One brief" in `docs/project-context.md`.
2. Delete `PROJECT.md`.
3. Update the link in `AGENTS.md`.

A site with only `PROJECT.md` renames it after mapping its sections. Delete `PROJECT.example.md`; `doctor` and `update:plan` report it as retired.

#### Link prefetch through speculation rules

_EmDash and static · components, docs, skills · Review and merge by hand; a decision per site · files: `src/lib/speculation-rules.ts`, `src/layouts/SiteShell.astro`, `src/layouts/Base.astro`_

`SiteShell` takes a new `prefetch` setting (`'off'` by default, `'conservative'` or `'moderate'`). When it is on, the page carries a static `<script type="speculationrules">` JSON block, so Chromium browsers fetch a likely next page ahead of the click with no script. The prefetched page is used for that navigation even though public HTML is sent `no-cache`, so pages stay fresh after every publish and still open quickly; other browsers ignore the block. It prefetches only and never prerenders. Internals (`/_*`), `/api/`, `/admin`, links with a query or fragment, downloads, other targets, `data-astro-reload` and `data-astro-prefetch="false"` are left alone. Until now no prefetch ran at all on sites without ClientRouter, because the hover warm-up only works with the router. Both starter Base layouts now pass `prefetch="moderate"`, and EmDash's Base turns it off in visual edit mode.

##### For sites

Copy `src/lib/speculation-rules.ts` and take the new `SiteShell.astro`. Then pass `prefetch="moderate"` to `<SiteShell>` in your `Base.astro` (EmDash sites: `'off'` when `getRequestContext()?.editMode` is true, as the starter does). Sites that added `<ClientRouter />` keep `prefetch` off. If `astro.config.mjs` turns on Astro's own `prefetch` or `experimental.clientPrerender`, remove them so only one prefetcher runs. On Cloudflare Workers Free, every prefetch counts toward the 100,000 daily requests; a busy site can use `"conservative"`, which waits until a click starts.

#### Real update dates in static sitemaps, slashless links flagged, HSTS and security.txt at cutover

_EmDash and static · tooling, content-model, skills · Review and merge by hand; a decision per site · files: `scripts/audit-html-integrity.mjs`_

Static posts take an optional `updatedAt`, which can never fall before `publishedAt`. The sitemap's `lastmod` uses it, falling back to `publishedAt` and never the build date, and post pages pass it as `dateModified`. The Sveltia profile gains a matching optional Updated field.

On EmDash sites, `audit:html` now flags a link from a prerendered page to a directory page without its trailing slash (`/about` for `about/index.html`). Static hosts answer such a link with a redirect, and Search Console reports the page as "Page with redirect". Static sites don't ship `audit:html`; the static profile already builds every internal URL with its slash through `routePath`.

The cutover skill adds two steps:

- enable HSTS at the TLS terminator in stages, without `preload`;
- publish `/.well-known/security.txt` with a contact and an `Expires` date under a year away.

##### For sites

- **Static sites:** add `updatedAt: z.coerce.date().optional()` to the posts schema, with the check that it is not before `publishedAt`. Use `p.data.updatedAt ?? p.data.publishedAt` for the sitemap `lastModified` and pass `modifiedAt={post.data.updatedAt}` from the post page. Sveltia sites also add the optional `updatedAt` datetime field to `public/admin/config.yml`.
- **EmDash sites:** take `scripts/audit-html-integrity.mjs` with the next helper sync and fix any `link-slash` it reports. The cutover steps arrive with the next skill sync.

#### Before/after comparison

_EmDash and static · components, docs · Copy the named files into the site · files: `src/components/BeforeAfter.astro`_

`BeforeAfter.astro` compares two pictures of the same view on one frame: renovations, gardens, treatments, restorations and redesigns. It is built on an invisible native range input over the picture:

- arrow keys, Home, End and screen readers work without extra code, and the read-out says how much of the before picture shows;

#### The cache rehearsal proves a missing page is never cached

_EmDash · tooling, docs · Copy the named files into the site · files: `tests/cache.integration.mjs`_

`npm run check:cache` now requests a missing post, page and tag twice each and requires a 404 that is not a route-cache hit, then publishes a post under the missing slug and requires it to render at once. Astro's memory cache stores any response that carries a lifetime, whatever its status, so a cached 404 would hide an entry published later; today the 404 rewrite is not stored, and this check keeps it that way across Astro and EmDash upgrades.

##### For sites

Copy `tests/cache.integration.mjs` when the site has not changed it, and run `npm run check:cache` after an Astro or EmDash upgrade or a new route rule. A site that customised the rehearsal adds the missing-entry block by hand.

#### A Content-Security-Policy computed from each page, report-only first

_EmDash · components, tooling, skills, docs · Copy the named files into the site · files: `src/lib/content-security-policy.ts`, `src/middleware.ts`, `src/env.d.ts`, `scripts/check-quality.mjs`_

With `CSP_MODE=report` or `enforce` in the build environment, the middleware adds a Content-Security-Policy to every public HTML response. The policy hashes each inline script and style the page actually carries, so scripts need no `'unsafe-inline'`. `style=""` attributes stay allowed, because Baseline uses them for layout values and they cannot run code. `CSP_SOURCES` adds third-party origins; it is checked when the server starts, so a malformed value fails then.

Mode `report` blocks nothing. The policy skips:

- `/_emdash/*`, where EmDash sets the admin's own policy;
- signed-in and editing requests;
- responses that already carry a policy;
- non-HTML responses.

`npm run check:quality` now reports `csp-violation` for anything the policy blocks or, in report-only mode, would block.

Astro's built-in `security.csp` was tried and not used. On Baseline's pages it blocked the inline shell script, two inline styles, EmDash's own inline style and the speculation rules, and it would have needed per-route exceptions for the admin. A policy computed from the final HTML covers all of these.

##### For sites

Copy `src/lib/content-security-policy.ts`, take the new `src/middleware.ts` (or add the `withContentSecurityPolicy` call before `withSecurityHeaders` in your own), add the two `ImportMetaEnv` entries to `src/env.d.ts`, and update `scripts/check-quality.mjs`. At the next deploy:

1. Build with `CSP_MODE=report` (plus `CSP_SOURCES` for analytics, embeds or fonts from elsewhere).
2. Run `npm run check:quality` and fix or allow each `csp-violation`.
3. After a week of clean checks, switch to `CSP_MODE=enforce`.

Sites with `<ClientRouter />` stay on `report` or `off`.

#### Wording rules checked on the text visitors read

_EmDash and static · tooling, skills · Copy the named files into the site · files: `scripts/check-quality.mjs`, `tests/check-quality.test.mjs`_

`page-budget.json` takes a `copy` list of wording rules, each with a `pattern`, `flags` (default `i`) and a `why`. `npm run check:quality` checks each rule on every route's rendered text and reports `copy-rule` with the match, its count and the surrounding words. It skips:

- code and quotations;
- hidden text;
- anything under `data-copy-ignore`, such as a client's own words.

Typical rules: a one-person studio says "I", never "we"; banned phrases from the art direction. `--init` keeps existing rules. Page text never appears in the saved report.

##### For sites

Copy `scripts/check-quality.mjs` and `tests/check-quality.test.mjs`. Then add the site's wording rules from its art direction to `page-budget.json` under `copy`.

#### Rendered-HTML parity for updates and refactors

_EmDash and static · tooling, docs · Copy the named files into the site · files: `scripts/html-parity.mjs`, `tests/html-parity.test.mjs`_

`npm run parity:html -- capture --base <origin> --sitemap --out <dir>`, run before and after a change, followed by `parity:html -- compare <before> <after>`, shows which markup changed on each route. Screenshots miss these changes: a heading level, a link target, an attribute, metadata or JSON-LD.

- **Normalized away** (build noise): hashed asset names, scoped-style and island ids, nonces, integrity and CSP hashes, and whitespace between tags. `--ignore <regex>` covers anything else that changes on every build.
- **Each route fetched twice**, so content that changes between requests is flagged instead of reported as a regression.
- **No browser needed.** It exits 2 on differences.
- **Tested on Baseline's own build:** a CSS-only change left all six routes unchanged.

The update guide now asks for it next to `capture:routes`.

##### For sites

Copy `scripts/html-parity.mjs` and `tests/html-parity.test.mjs` (it uses `scripts/audit-ui.mjs` and `scripts/capture-routes.mjs`, which sites already have) and add `"parity:html": "node scripts/html-parity.mjs"` to `package.json`. Use it around every Baseline update.

#### Route quality gates with a per-site page budget

_EmDash and static · tooling, skills, docs · Copy the named files into the site · files: `scripts/check-quality.mjs`, `tests/check-quality.test.mjs`_

`npm run check:quality -- --base <built origin> --sitemap` fails a route that has quietly got worse, where `audit:page` only observes. On every route, in a fresh browser context, it checks:

- the weight of the HTML, inline CSS, scripts, images, the largest-paint image and font preloads;
- layout shift while the page loads and is scrolled;
- a heading or image on the first screen that starts transparent or clipped;
- hydrated `<astro-island>` components;
- JSON-LD that does not parse, or lacks the types the budget lists;
- tap targets under 24px that crowd a neighbour (WCAG 2.5.8);
- a Tab stop hidden behind a sticky bar (WCAG 2.4.11).

Limits come from the site's own `page-budget.json`, which Baseline never ships or syncs; without it the defaults apply. `--init` writes the file from the current numbers plus 25%, giving any heavier route its own entry with a `_why` to fill in. The cutover skill runs it before cutover and after every deploy, and the rollout reference describes it.

##### For sites

Copy `scripts/check-quality.mjs` and `tests/check-quality.test.mjs` (it also needs `scripts/audit-ui.mjs` and `scripts/capture-routes.mjs`, which sites already have), and add `"check:quality": "node scripts/check-quality.mjs"` to `package.json`. Build the site, serve it, run `npm run check:quality -- --base <origin> --sitemap --init`, fill in each `_why` and commit `page-budget.json`. From then on, run it without `--init` after every deploy.

#### Titles, descriptions and JSON-LD graphs checked across the site

_EmDash and static · tooling, skills · Copy the named files into the site · files: `scripts/check-quality.mjs`, `tests/check-quality.test.mjs`_

`npm run check:quality` now reports four more kinds of issue:

- **`title`:** missing, or over 60 characters.
- **`description`:** missing, or outside 70 to 160 characters, on indexable routes. Noindex and error pages need only a title.
- **`duplicate-title` / `duplicate-description`:** the same text on more than one indexable route.
- **`json-ld`, three new cases:** an `@id` defined twice, a reference to an `@id` the page never defines, or a rating or review on the site's own organization. Google never shows that last kind and treats it as self-serving.

All three limits can be changed per route in `page-budget.json` (`titleChars`, `descriptionMinChars`, `descriptionMaxChars`).

The content-modeling skill gains field rules: an SEO description on every entry, an optional short title for long names, and summary lengths enforced where editors type.

On Baseline's own demo content it found pages that fall back to the site tagline, all sharing one 17-character description.

##### For sites

Copy `scripts/check-quality.mjs` and `tests/check-quality.test.mjs`, run `npm run check:quality`, and give each reported page its own title and description. A page that falls back to the tagline shares it with every other such page.

#### Contact forms: score suspicious submissions, flag or hold them, never lose one

_EmDash · skills · Arrives with the site's skill or source sync_

The contact-forms reference of the production cutover skill gains a section on what gets past the honeypot and rate limit:

- store every accepted submission first, then score it, with each signal adding points and a reason a person can read;
- mail messages below a flag line as normal, mail those above it with a subject marker and the reasons at the top, and only store those above a hold line;
- list held submissions for the owner and never delete them automatically;
- calibrate the thresholds on the site's own stored spam;
- treat request country and unsigned timing fields as weak signals;
- set a retention period and name the storage in the privacy notice.

Two acceptance rows cover the flag and hold paths.

##### For sites

Take the skill with the next skill sync. A site with a native contact form should add scoring when spam starts reaching the inbox, starting with a flag line only and adding a hold line once the stored spam shows where it should sit.
