# Opt-in public-feed HTML caching

The optional `src/lib/public-feed-cache.ts` helper keeps request-owned evidence from every successful feed part and applies a final absolute lifetime constraint after rendering. `src/lib/private-safe-memory-cache.mjs` wraps Astro's public `astro/cache/memory` provider with a bypass for non-GET requests, Authorization, every Cookie and every query before cache lookup. Native storage, tag invalidation and expiry remain delegated. Neither helper enables routes or installs a plugin. Both are EmDash/SSR-only inventory entries, omitted from generated static profiles.

## Host contract

Use an SDK that validates the source protocol. Eventual 0.15.0 is one supported consumer: its `publicFeedCacheOptions()` validates versioned dependencies and expiry and enforces a 15-second ceiling. Read its [integration guide](https://github.com/Vermeulen-Solutions/eventual-emdash-sandbox/blob/v0.15.0/docs/public-feed-caching.md) and verify the source package and backend versions together. Baseline adds no Eventual dependency, collection names or plugin ownership changes.

At request start, create one state with `createPublicFeedCacheState()`. Pass it explicitly through query helpers. Call `recordPublicFeed(state, parsedFeed, rendererBoundaries)` for every successful result, including empty splits. Retain every original absolute expiry. Failed terminal splits/renderers set `state.failed = true`; a retryable failed parent resolved completely by child results is not itself an evidence part. Never key state by a shared runtime singleton.

After all components and CMS queries finish, buffer the HTML and call `finalizePublicFeedCache(state, sdkResolver, chosenMaxAge)`. It uses the current clock, passes all metadata/boundaries to the SDK and adds request-start plus the host budget as an upper bound. It rejects missing state/evidence, failures, invalid clocks/TTLs, resolver errors, unsafe tags, noninteger/extended lifetimes and stale-serving options. The SDK owns protocol validation, including unsupported versions and expired/future evidence; this helper alone cannot certify source freshness.

Apply the result only inside the host's final response guard: reviewed route, anonymous GET, supported URL, no authorization/session/cookies, status 200, HTML, no actual/pending Set-Cookie, no private response policy and no failed dependency. Include other rendered CMS hints and their expiry constraints. Finalize excluded/failed responses with `cache.set(false)` and appropriate no-store policies. Astro scalar options use last-write-wins: later helpers must not widen TTL or re-enable rejected output. Bare tags can enable Cloudflare's implicit lifetime without a route rule.

## Provider and browser policy

For an explicitly enabled single-instance Node host, retain `memoryCache({ query: { exclude: [] } })` and replace its entrypoint with the private-safe wrapper. Consult the installed [Astro caching APIs](https://docs.astro.build/en/guides/caching/). Private/query requests bypass an anonymous entry and cannot replace it. Multiple processes still need a shared provider or acceptable bounded TTL.

Cloudflare's front-of-Worker cache cannot use this Node bypass. Signed-in browsers can receive cached anonymous HTML before middleware runs. Exclude session-dependent output; verify supported client-toolbar/editor entry, URL/query keys and the actual hosting layer. Use `src/lib/cloudflare-cache-provider.mjs` on Cloudflare Workers so anonymous `200` HTML is stored in the Worker's `caches.default` after the Worker verifies the request has no `Cookie`, `Authorization` or query string, while returning `Cloudflare-CDN-Cache-Control: no-store` so Cloudflare's outer CDN never serves cached anonymous HTML to cookie-bearing editor requests on `*.workers.dev`. When a sandboxed feed plugin (such as Eventual 0.15.0) emits a short internal 15-second feed `expiresAt` on a site where events change infrequently and the host's public HTML cache policy is 1 hour (`PUBLIC_CACHE_SECONDS = 3600`), validate every feed split and dependency tag via `finalizePublicFeedCache`, and compute the HTML `maxAge` as `Math.min(PUBLIC_CACHE_SECONDS, boundaryCap)` where `boundaryCap` is the seconds until the next Renderer Boundary (next upcoming event `startAt`/`endAt` transition or UTC midnight rollover) rather than clamping homepage and calendar HTML caching to 14 seconds. Build/header checks cannot establish hosted HIT/purge behavior. Enable affected hosted routes only after their backend and hosted acceptance gate pass.

Choose browser policy separately: no-cache, or a lifetime no longer than the final remaining HTML lifetime, with correct Date/Age accounting. Never mint a full new TTL for aged metadata/CDN HTML. Disable SWR and stale-on-error at every layer. JSON feeds, calendars and images retain independent contracts: API response caching does not register parent HTML dependencies.

Eventual-specific limitations include runtime site-identity snapshots, generic plugin/settings writes and Node scheduling without complete route invalidation. Tags cannot promise immediate freshness for every mutation. Identity changes may require a restart; TTL cannot repair stale source inputs. No sandbox cache API or public purge endpoint is introduced.

## Acceptance

Run `node --test tests/public-feed-cache.test.mjs tests/private-safe-memory-cache.test.mjs`. Synthetic evidence and the actual memory provider cover HTML HIT/invalidation, private/query bypass, request isolation, earliest split/render expiry, Set-Cookie refusal and no stale-on-error after expiry.

Sites additionally need compiled parent HTML tests with their actual SDK/backend: drafts, publication/unpublication/deletion/restoration, first publication into an empty feed, related directory/settings edits, time/all-day/DST boundaries, metadata failures and injected purge failure with bounded refresh. Use a disposable instance and synthetic content. Hosted cache/Registry behavior is a separate observed gate. Source helper tests are not a deployment certificate.
