# Reviewed skill synchronization

Both helpers default to staging, without replacing managed files. Use `npm run sync:emdash-skills -- --check` or `npm run sync:site-skills -- --check` for read-only comparisons. A matching upstream commit does not prove local cleanliness. Missing/unavailable source evidence fails rather than claiming synchronization. GitHub's public API/raw endpoint is used first; authenticated `gh api` supplies private/rate-limited source access without printing tokens. Downloads resolve an immutable commit and verify each Git blob.

Use `--stage [--ref <commit-or-tag>]` to save candidate files and `review.json` under ignored `.emdash/skill-sync/<id>/`. Review a diff against `.agents/skills/`, source provenance, licenses, local extras and missing files. No managed skill is replaced by staging. A legacy commit-only receipt is compared against actual old upstream bytes. With no ownership receipt, existing files are unowned and need explicit resolution; they are never assumed disposable.

Apply with `--apply <id>`. The helper rechecks current files, receipt and staged hashes, takes an exclusive lock, renames each managed directory through a retained backup, and publishes the ownership manifest only after replacement. UTF-8 text hashes normalize CRLF to LF; binary bytes remain binary. Symlinked managed paths and truncated upstream trees are refused. Manifests and upstream licenses/files remain separate from project overlays.

If the review lists conflicts, prepare a resolution JSON containing `reviewSha256` (SHA-256 of the exact review.json bytes) and `replacePaths` (exact sorted paths from its conflicts list). Pass it with `--resolution <file>`. This acknowledges the reviewed replacement, including deleted/extra files; all originals remain in the stage's backup. Preserve valuable policy in maintained guidance or prepare an upstream patch before selecting replacement. Do not blindly approve all conflicts.

Caught failures roll back directory replacements and the old manifest. On Windows, a process holding files open under `.agents/skills` (usually a running `astro dev` or `wrangler dev`, sometimes an editor, indexer or antivirus scan) makes a directory rename fail with `EPERM`, `EBUSY` or `EACCES`. The helper retries each rename for about 1.5 seconds. If the lock persists, it rolls back and names the likely cause. Stop the dev server first, then run the same `--apply <id>` again: a cleanly rolled-back stage can be re-applied after all checks pass, without restaging. After a process/host interruption, inspect `.emdash/skill-sync.lock` (PID/time) and the stage journal. Only after verifying that process is no longer running, remove that stale lock and use `--recover <id>`. Recovery refuses later changed target bytes instead of deleting them. Keep the journal/backups until the recovered state is reviewed. This is a journaled multi-directory transaction with per-directory atomic renames; it does not claim a filesystem-wide atomic commit or protection against an independent editor changing a file during apply. Stop other skill writers before applying.

**Checking an older site, line endings and profile manifests.** `--root <site>` runs a read-only `--check` against another site from this checkout, so a site whose helper predates the drift report can still be checked; staging and applying always use the site's own helper. `notInstalled` and `helper` are always reported. On apply, a text file that is CRLF in the site stays CRLF (hashes already normalize line endings), and when the site carries Baseline's `profiles/manifests/shared.json`, new files of skills it already ships are added to `skillFiles` and reported as `profileManifestAdded`.

**Membership and the helper itself.** A site's managed skills are the helper's built-in list plus any skill it added earlier, as recorded in its manifest. `--check` and `--stage` report `notInstalled`: upstream skills at that commit that this site does not manage (mirrored EmDash skills are excluded). Stage one deliberately with `--stage --add-skill <name>`; the apply records it in the manifest so later syncs keep it. Both commands also report `helper`: whether the installed `scripts/skill-sync.mjs` matches the upstream helper at the staged commit (LF-normalized Git blob hash). Skill sync never replaces the helper; when it `differs`, adopt the upstream helper as a reviewed change. Options are strict: unknown or repeated flags, and `--ref`/`--add-skill` combined with `--apply`/`--recover`, are refused.

The site distribution includes emdash-content-modeling. `.emdash/impeccable-source.json` records the current curated distribution/hash and license evidence; matching LICENSE and PROVENANCE.json files accompany the skill for downstream distribution, without changing its upstream instructions; the launcher version is distinct from the skill version. No claim is made that an unknown bundled source commit is verified. The two pre-existing modified EmDash mirror files remain preserved and staged for review; the new helpers do not silently replace them.

Canonical starter maintenance must publish reviewed local improvements before downstream sites can fetch them. Running a site-skill refresh against this same repository's older remote commit would otherwise replace newer local policy; local-drift resolution protects against that.

The maintained site inventory includes `opendesign-site-design`, `openpencil-site-design`, and `penpot-site-design`. Each is Baseline-owned and ships with references, templates, and optional MCP metadata. They can be staged and reviewed alongside other maintained skills without requiring external desktop applications or account credentials during file synchronization. Older static sites can adopt these skills along with [docs/opendesign-onboarding.md](opendesign-onboarding.md), [docs/openpencil-onboarding.md](openpencil-onboarding.md), or [docs/penpot-onboarding.md](penpot-onboarding.md) as reviewed local additions.

`openpencil-site-design/references/upstream/` is a separately licensed, unmodified OpenPencil mechanics snapshot bundled inside the Baseline adapter. Its `PROVENANCE.json` records the exact upstream release/commit, source paths and LF-normalized SHA-256 hashes. It is not an EmDash mirror and has no invented synchronization receipt. To refresh it, explicitly review the installed app/MCP compatibility, download all recorded files including the license from an immutable upstream commit, inspect their changes, update the provenance and rerun the practical recipe/persistence tests. Keep Baseline policy outside that directory. Normal site-skill staging carries the complete reviewed snapshot; it must not independently fetch current OpenPencil `master` or alter app/client installations.
