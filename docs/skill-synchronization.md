# Reviewed skill synchronization

Both helpers default to staging, without replacing managed files. Use `npm run sync:emdash-skills -- --check` or `npm run sync:site-skills -- --check` for read-only comparisons. A matching upstream commit does not prove local cleanliness. Missing/unavailable source evidence fails rather than claiming synchronization. GitHub's public API/raw endpoint is used first; authenticated `gh api` supplies private/rate-limited source access without printing tokens. Downloads resolve an immutable commit and verify each Git blob.

Use `--stage [--ref <commit-or-tag>]` to save candidate files and `review.json` under ignored `.emdash/skill-sync/<id>/`. Review a diff against `.agents/skills/`, source provenance, licenses, local extras and missing files. No managed skill is replaced by staging. A legacy commit-only receipt is compared against actual old upstream bytes. With no ownership receipt, existing files are unowned and need explicit resolution; they are never assumed disposable.

Apply with `--apply <id>`. The helper rechecks current files, receipt and staged hashes, takes an exclusive lock, renames each managed directory through a retained backup, and publishes the ownership manifest only after replacement. UTF-8 text hashes normalize CRLF to LF; binary bytes remain binary. Symlinked managed paths and truncated upstream trees are refused. Manifests and upstream licenses/files remain separate from project overlays.

If the review lists conflicts, prepare a resolution JSON containing `reviewSha256` (SHA-256 of the exact review.json bytes) and `replacePaths` (exact sorted paths from its conflicts list). Pass it with `--resolution <file>`. This acknowledges the reviewed replacement, including deleted/extra files; all originals remain in the stage's backup. Preserve valuable policy in maintained guidance or prepare an upstream patch before selecting replacement. Do not blindly approve all conflicts.

Caught failures roll back directory replacements and the old manifest. After a process/host interruption, inspect `.emdash/skill-sync.lock` (PID/time) and the stage journal. Only after verifying that process is no longer running, remove that stale lock and use `--recover <id>`. Recovery refuses later changed target bytes instead of deleting them. Keep the journal/backups until the recovered state is reviewed. This is a journaled multi-directory transaction with per-directory atomic renames; it does not claim a filesystem-wide atomic commit or protection against an independent editor changing a file during apply. Stop other skill writers before applying.

The site distribution includes emdash-content-modeling. `.emdash/impeccable-source.json` records the current curated distribution/hash and license evidence; matching LICENSE and PROVENANCE.json files accompany the skill for downstream distribution, without changing its upstream instructions; the launcher version is distinct from the skill version. No claim is made that an unknown bundled source commit is verified. The two pre-existing modified EmDash mirror files remain preserved and staged for review; the new helpers do not silently replace them.

Canonical starter maintenance must publish reviewed local improvements before downstream sites can fetch them. Running a site-skill refresh against this same repository's older remote commit would otherwise replace newer local policy; local-drift resolution protects against that.
