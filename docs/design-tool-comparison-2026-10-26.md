# Baseline design-surface trial — 2026-10-26

## Recommendation

Recommend **canvas-led iteration** for new sites and substantial visual overhauls, offering **OpenPencil**, **Penpot** and **direct Astro/browser** explicitly. Prefer an already working user-preferred canvas: OpenPencil suits local desktop/files, Penpot suits shared cloud access and sequential agents across machines. Direct Astro remains complete when the user prefers it or browser behavior dominates the design question. Small refinements can stay in their accepted surface. Use one representative concept slice, focused visual changes, direction selection, then an Astro proof before rollout; avoid recreating the whole site on both surfaces. Same-agent work is complete. The final pass adopts the user's preference for a comfortable design-tool review experience; the pilot did not establish a timed speed advantage.

This recommendation is based on the practical scope below, not a claim that one tool consistently makes better designs, costs fewer tokens or supports every model. The same agent produced both trials; font metrics and layout implementation differ. A broad visual-quality/model benchmark would need multiple briefs and independent runs. No third-party free-tier limit is assumed permanent.

For this user's agent-driven Baseline work, the practical starting recommendation is **OpenPencil**, especially when its local setup is already available. Its declarative scene authoring and native layout fit the task of expressing/revising page relationships; the pilot used those directly, while the Penpot prototype used more imperative scripting and manual positioning repairs. This is an authoring-fit judgment, not evidence that Penpot lacks native layout or that OpenPencil produces better designs with every model. The approaches were not controlled equivalents. Prefer **Penpot** when shared browser access, client review or sequential work across machines without local-file transfer is the stronger requirement. Visual quality still depends on the brief, model, Baseline framework and feedback loop; neither canvas supplies design judgment automatically.

## Failures and repairs

- Penpot initialization succeeded while canvas calls failed because the tab slept. The user woke it; read-only identity then passed. Onboarding now distinguishes transport, plugin/tab and target checks.
- `findByName('Noto Sans')` returned Noto Sans Ogham. Exact family/weight lookup resolved it; the skill now documents this concrete failure.
- The first Penpot mobile board omitted the second panel. It was added, the board extended for lower content, and complete text recovered in a fresh session. Absolute positioning needed manual vertical spacing after the longer title; a separate native-flex/component specimen was also tested.
- OpenPencil's initial card title grew past the mobile panel. Fill width and height auto-resize repaired it; the intentional heading measure needed Fixed width. Native flex then handled surrounding spacing. Save/reopen changed IDs, so recovery must use file identity and fresh target inspection.
- OpenPencil settings rejected document IDs because that global tool has a different schema. The guide says to inspect individual schemas rather than append target IDs blindly.
- The first browser screenshot after a width/navigation change was cropped to about 374px despite a requested 390px. Stable content/root bounds and saved image dimensions were inspected; final study captures are exactly 390/768/1440px wide. Styleguide viewport captures were 375/1425px due this desktop scrollbar/capture behavior and are recorded as such, not presented as exact 390/1440 captures. This reinforces checking capture dimensions instead of diagnosing a gutter from an unvalidated image.
- The new onboarding document initially lacked a shared file-inventory classification. Distribution tests caught it; explicit inventory/allowlist entries repaired it. A second test proves adding Penpot membership stages candidates while preserving local guidance and refusing unresolved replacement conflicts.
- Full verification then exposed a hard-coded four-skill contract in the self-contained static updater. It now accepts the historical four-skill set and current five-skill set, and selects skill updates from the site's installed set. A regression test keeps an old config and ownership membership unchanged, refuses fetching/adopting Penpot even with an accidentally retained managed record, and rejects a forged stage entry. Ordinary apply audit metadata can still record the operation. New generation does not force old installations into a membership migration.

## Acceptance bounds and verification

The pilot deliberately uses synthetic copy and neutral starter tokens; it is not client design approval. The packet labels agent self-selection as synthetic. The initial canvas colors were illustrative; final role bindings use sampled source values while retaining the original OKLCH/fluid expressions. Noto Sans/Libre Baskerville/Source Code Pro in Penpot and Arial/Georgia/Consolas in OpenPencil are documented canvas substitutions for the starter's system stacks; no pixel-fidelity verdict follows. Browser typography, gutters, card padding and responsive pacing follow native source contracts rather than absolute canvas coordinates.

The generated `/_styleguide` was inspected at wide/narrow settings. The native study preserved all text and both panels; 390px stacks in source order, while 768/1440 use the source bento reflow. Its card link and hero destinations are real in-page targets. Keyboard Tab reached the skip link and primary action with solid focus outlines; the native disclosure opened and the following calibration button received visible focus. Three action roles and a disabled specimen were rendered. This test does not certify CMS edit/save/reload, real submissions, sticky/reveal/View Transition timing, reduced-motion variations or all client routes; no such behavior was changed in the template.

Skill metadata validation and targeted profile/update tests passed during implementation. Final verification passed 336 tests (185 unit, 151 rehearsal), with Astro's 53 files clean. Release build, HTML audit (9 HTML files, 10 public SSR responses), production isolation and both independently installed static profiles passed. The translation pilot separately type-checked 36 files and built `/study/`. Full command scope and the profile harness's separate browser limitation are recorded in the implementation plan. No client deployment is applicable to this template-only release.
