# Starter meta-review (initial runbook)

This is the starter meta-review runbook. The scoped `0.1.0` standards baseline records upstream diagnostics, staged sync, private registration and the tested Node/SQLite/Windows browser profile. Use the exact release reference and scope in `standards/manifest.json`, not mutable main or historical candidate claims. Use npm and the lockfile. Run `npm run audit:baseline` for a read-only JSON observation of declared, locked and installed packages, Node, Git state and local skill hashes. Missing evidence is unverified; this command does not contact upstream, read CMS rows or certify compatibility.

## Review sequence

1. Preserve and review the existing working tree; record its revision and scope. Run existing unit checks, typecheck and build. Inspect actual collection widths separately using check:schema-budget; a missing DB is unmeasured even if the legacy check exits zero.
2. At every meta-review, compare Astro, official adapters/integrations, Node, EmDash and affected tooling against current stable/patch releases using official documentation and registries. New stable Astro releases trigger evaluation independently of EmDash. Read intervening changelogs, migration guides, engine/peer requirements, security/support changes and deprecations. Do not run an unreviewed upgrade command as diagnosis.
3. Record candidate, review date/owner, benefit/risk, affected code/docs/skills, compatibility/test evidence, adopt/defer/not-applicable decision and a revisit trigger. Major versions need a migration spike; experimental/prerelease features are opt-in. The lockfile is a baseline, not an upgrade ceiling.
4. For the current candidate, evaluate [Astro 7.4](https://astro.build/blog/astro-740/): Node >=22.22 versus the starter's >=22.16 declaration, separate build/runtime image services, Cloudflare adapter/Wrangler peers, build --timings, font-provider warnings and conditional custom-entrypoint notFound behavior. Keep experimental parallel prerendering/static redirect templates off without demonstrated need. Test SSR CMS media added after build and actual editor saves. The detailed roadmap records applicability and proposed tests.
5. Stage upstream skill refreshes on a disposable copy when managed files are dirty; inspect the diff before replacement. Local editorial policy belongs in AGENTS.md and maintained skills. Existing sync manifests do not prove unmodified local content. Use docs/skill-synchronization.md for hash-aware staging, reviewed exact-path replacement, backup and recovery. The maintained distribution includes emdash-content-modeling.
6. Select exact candidate versions in a reviewable change; test fresh setup and existing-database upgrade with recoverable disposable data/media. Node and Cloudflare are distinct evidence profiles. Reverting npm packages does not restore a migrated DB.
7. Certify only shipped checks: public/editor, native images, gallery order/captions, locales, query hints when caching is enabled, keyboard/reflow and production exposure. Add the visual harness and DB/media adapters as they ship. Publish tested versions, limitations, migration/restore instructions and the standards release. Downstream audits consume that release, not mutable main.

## Current boundaries

Node + SQLite/local storage is the default; Cloudflare remains optional. The baseline command itself performs no upgrade, remote mutation, synchronization or registration. Phase 2 separately updates the tested Node package matrix and supplies local proposals; see standards/manifest.json and audit/phase-2/README.md. Existing uncommitted schema/editorial additions remain separately attributable. See audit/phase-1/ for implementation evidence and audit/roadmap-review-2026-10-15/ for issue contracts and phased work.
