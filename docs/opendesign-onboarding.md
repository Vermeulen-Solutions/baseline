# OpenDesign: setup and review by comments

OpenDesign (`nexu-io/open-design`) is a local HTML/CSS design app with a preview the owner can comment on. Baseline recommends it when the owner wants to **review designs by marking what should change**: the agent builds the concepts as HTML/CSS artifacts, the owner clicks on an element and leaves a short note, and the agent reads each note with its element (`npm run design:comments`), changes that element, checks the render and marks the note resolved. The owner never edits a canvas by hand. HTML/browser concepts remain the default without a canvas request; OpenPencil (vector boards, also reviewed by comments), Brilliant (hand editing) and Penpot (shared cloud review) remain explicit choices. Its systems/templates are available through shared reference research without selecting or installing the app. Reuse an already working user-preferred connection; use [opendesign-site-design](../.agents/skills/opendesign-site-design/SKILL.md) and [design-iteration.md](../.agents/skills/site-art-direction/references/design-iteration.md) for focused concept edits followed by a representative Astro proof. Existing art-direction, CSS/component contracts and acceptance gates apply on every surface.

## Setup

Install OpenDesign Desktop from the [official repository](https://github.com/nexu-io/open-design). The desktop installation includes the prebundled daemon CLI (`resources/app/prebundled/daemon/daemon-cli.mjs`, on Windows typically under `%LOCALAPPDATA%\Programs\Open Design\resources\app\prebundled\daemon\daemon-cli.mjs`) and the local catalog under `resources/open-design/` (154 `DESIGN.md` design systems, 188 HTML/CSS layout examples, 116 templates and 13 workflow atoms). Never add OpenDesign packages to a site's `package.json` or lockfile.

When OpenDesign Desktop is running, it spawns two local loopback servers:

1. **The OpenDesign Daemon** (standalone CLI default `http://127.0.0.1:7456`, or an ephemeral desktop port such as `11285`): serves `/api/projects`, `/api/active`, `/api/plugins/*`, artifact storage, `od lint` and headless Chromium `od export`.
2. **The Next.js Web Sidecar** (for example `http://127.0.0.1:6409` or `http://127.0.0.1:6411`): serves the React workspace UI rendered inside the Electron shell and in standard web browsers.

The comment loop needs only the running desktop app: `npm run design:comments` finds the daemon by itself (or takes `--daemon` / `OD_DAEMON_URL`). The MCP server is optional, for project and file tools. To register it, copy the command OpenDesign generates under **Settings → OpenDesign MCP** for your agent (for Claude Code, a `claude mcp add-json --scope user open-design …` line) and run it once; Claude Code then reports it as connected under `claude mcp get open-design`. That command holds machine-specific paths (the app version folder and a local pipe name), so never commit it, and copy it again after an app update or when the server times out at session start. See [connection-and-cli.md](../.agents/skills/opendesign-site-design/references/connection-and-cli.md) for port discovery and CLI commands.

## How a review round goes

1. For a page that already exists, the first round is a copy of the live page (one self-contained file) that the owner marks before any new direction is drawn.
2. The agent builds two or three directions as HTML artifacts in one OpenDesign project, with a `data-od-id` on every element the owner might point at, and checks them at 1440 and 390.
3. The agent gives the owner the steps in chat every round, with the real names: press `Ctrl + R` in the desktop app (the window does not pick up files written from outside), open the project and its **Design Files** tab, open the named file, choose **Comment** in the preview toolbar, click on what should change, type a short note and choose **Comment** (not **Send to chat**, which hands it to OpenDesign's own agent). Picking a version with no notes is a complete answer.
4. The owner tells the agent they are done. The agent lists the notes (`npm run design:comments -- --project <id>`), changes each element, checks before and after renders, marks each note resolved (`--resolve <comment-id>`) and reports in chat what changed, with the images. A note it cannot act on gets a question and stays open.

In Baseline's trial (0.27.2), reading two notes took 40 ms, and the round from reading to resolving, with both fixes checked at 1440 and 390, took about 30 seconds of tool time. Each note arrived with its element's selector and text, so no matching by position was needed.

## Bundled Baseline plugins and source token bootstrap

Baseline ships two OpenDesign plugins inside the skill directory that validate cleanly with `od plugin validate` and `od plugin doctor`:

- **[Baseline Astro Design System](../.agents/skills/opendesign-site-design/assets/plugins/baseline-design-system/DESIGN.md) (`design-system-baseline-astro`):** Defines Baseline's 3-tier OKLCH surfaces (`--color-page`, `--color-surface`, `--color-elevated`), 4-voice fluid typography (`--font-display`, `.font-accent`, `--font-body`, `--font-mono`), fluid `clamp()` scales (`--text-step-*`, `--spacing-*`) and structural HTML classes (`.section`, `.container`, `.bento-grid`, `.card`, `.flow`, `.btn`).
- **[Export to Baseline Astro](../.agents/skills/opendesign-site-design/assets/plugins/od-astro-baseline-export/SKILL.md) (`od-astro-baseline-export`):** Wraps OpenDesign's `handoff` atom with Baseline's 5-step transmutation protocol (`AGENTS.md` Art Direction Gate → `src/styles/global.css` token sync → `/_styleguide` zero-JS Astro primitive decomposition → EmDash/static data bindings → route verification).

For an existing Baseline site redesign or component refinement, run `npm.cmd run design:canvas-kit -- --out ../canvas-kit-001` ([canvas-kit.md](canvas-kit.md)) to emit a site-derived `open-design/DESIGN.md`, `open-design/open-design.json` and `open-design/specimen.html` bound to the site's active `src/styles/global.css`.

## Practical Acceptance & The Agent Switch

Follow the [HTML/CSS recipe](../.agents/skills/opendesign-site-design/references/baseline-html-recipe.md) when iterating concepts:

1. **Stage 4A (Shared References vs. Active Tokens):** Reuse the selected references from [shared reference research](../.agents/skills/site-art-direction/references/reference-research.md). On any surface, public/local system and template files can inform layout anatomy and aesthetic direction without the app or daemon. A connected project's `od plugin search <query> --json` or MCP `list_plugins` is optional transport, not a catalogue-first requirement. Adapt selected sources with the common reference pass and map chosen colors and fonts onto Baseline's `--color-*`, `--text-step-*` and `--spacing-*` custom properties. For existing sites, bind the extracted `design:canvas-kit` tokens.
2. **Stage 4B (Project Creation, preflight & export):** Create the project with an explicit lowercase slug `id` (`{ id, name }`). Author self-contained `.html` slices with `data-od-id` section anchors, run `npm run design:artifact-check -- <file.html> --opendesign --json` when installed (see [artifact lint](artifact-lint.md)), resolve P1 findings and review P2 evidence. Native `od lint <file.html> --fail-on p1 --json` remains optional for app/seed policy or older installations; reconcile its aesthetic opinions with the accepted direction. Register the artifact (`od artifacts create`) and capture `1440×900` and `390×844` renders with the [explicit-viewport export procedure](../.agents/skills/opendesign-site-design/references/connection-and-cli.md#explicit-desktop-and-mobile-captures). Source lint does not measure contrast or clipping.
3. **Where the owner looks.** For review by comments the owner uses the desktop app, the only place comments can be left. For a quick look without commenting, the artifact file itself is enough: artifacts are plain files under `%APPDATA%\Open Design\namespaces\<channel>\data\projects\<id>\`; open the `.html` directly (or serve the folder) while the desktop window stays closed. The window is only a cache: it does not open artifacts written by an external client, and `POST /api/active` is not read back by the UI — see [reviewing without the desktop UI](../.agents/skills/opendesign-site-design/references/connection-and-cli.md#reviewing-an-artifact-without-the-desktop-ui). If the owner wants the desktop view anyway, press `Ctrl + R` (`View -> Reload`) or open the web sidecar URL; the upstream sync fix is [nexu-io/open-design#8964](https://github.com/nexu-io/open-design/issues/8964) with PR [#8968](https://github.com/nexu-io/open-design/pull/8968), unmerged as of 0.27.0. To review live instead of refreshing by hand, run `npm run design:watch -- --project <id>`: it opens each changed artifact in the default browser.
4. **Stage 4C (Handoff & Agent Switch):** Baseline supports both single-agent workflows and multi-agent delegation:
   - **Single-Agent Model:** The same agent runs design iteration in OpenDesign, verifies `od lint`, exports renders, updates `AGENTS.md` and `src/styles/global.css` (`npm run design:tokens`), and implements the Astro templates.
   - **Multi-Agent Model (Agent Switch):** A design agent authors the OpenDesign concept and exports a handoff packet under `audit/visual-concepts/<concept-name>/` (including rendered images, HTML slices, and token mapping). An implementation agent then picks up the folder, seeds the Art Direction Record, calibrates components on `/_styleguide`, and builds the production Astro routes.
